# 지금까지의 프로젝트 이해와 작업 기록

2026-10-21 기준으로 대화, 검토한 기획 문서, 데이터 준비 결과물을 정리했다. 최초 작성 당시에는 로컬 루트 `README.md`를 비워두고 이 문서에 작업 내용을 모았다. 자료 공유용 PR에서는 원격 MVP의 README를 유지한다. 실제 코드 확인 이후의 차이와 추가 검토는 [MVP 코드·모델 검토](research/MVP_CODE_AND_MODEL_REVIEW.md)에 정리했다.

## 프로젝트를 어떻게 이해했는가

프로젝트는 사용자가 직접 측정한 혈당을 기록하고, 지난 기록을 살펴보며 일상 관리를 돕는 당뇨관리 웹앱이다. 닥터다이어리를 참고하되, 현재 준비 범위에서는 측정 기기 연동 없이 수동 입력을 전제로 했다. 도시 생활과 데이터 기반 사회혁신이라는 주제에서 일상 건강관리와 건강정보 접근을 돕는 방향으로 이해했다. 도시 단위 분석이나 실제 건강 개선 효과를 입증한 상태는 아니다.

기본 흐름은 로그인과 동의, 혈당 입력, 기록 목록과 그래프 확인, 수정·삭제다. 기록에는 혈당값·실제 측정 시각·측정 상황을 남기고 식사 메모는 선택 항목으로 이해했다. 입력 부담을 줄이기 위해 많은 생활 정보를 처음부터 필수 입력으로 요구하는 방향은 피했다. 입력 기본값이나 항목 축소의 사용성 효과를 실제로 시험한 것은 아니다.

초기 기획은 로그인과 기록지 중심이었다. 이후 데이터를 활용하는 기능으로 챗봇이 논의됐고, 본인 기록의 변화 설명과 일반 당뇨 지식을 제공하는 방향으로 구체화했다. 검토한 최신 문서 개정 5.0에는 선택 동의에 따른 본인 기록 요약, 출처가 있는 일반 지식 답변, 교육용 식단·운동 예시, 사용자 혈당 CSV 가져오기가 추가 설계로 제시돼 있다.

여기서 데이터의 역할을 세 가지로 나눴다.

| 데이터 | 역할 | 구분한 이유 |
| --- | --- | --- |
| 앱 이용자가 직접 입력한 혈당 기록 | 본인 기록 조회·기간별 요약·같은 측정 상황의 비교 | 실제 서비스에서 설명할 개인 기록이기 때문 |
| 질병관리청·대한당뇨병학회의 지침과 교육자료 | 일반 지식과 식사·운동 원칙을 설명하는 근거 | 개인 기록의 수치만으로 답할 수 없는 교육 내용이기 때문 |
| 식품 영양성분 자료 | 식품별 기준량·영양정보의 참고, 교육용 식단 재료 연결 | 식품명만으로 영양값이나 먹은 양을 추측하지 않기 위해 |

국민건강영양조사 자료는 조사 대상자의 검진·섭취 자료이므로 앱 회원의 기록과 구분했다. 집단 특성을 살펴보거나 변수 의미를 이해하는 데 활용할 수 있지만, 현재 확보한 추출본만으로 특정 사용자의 식후 혈당이나 미래 혈당을 예측할 수 있다고 보지 않았다.

평균·최솟값·최댓값·건수·변화량은 코드가 계산하고, 챗봇은 확인된 결과를 설명하는 방식으로 잡았다. 공복과 식후 기록을 섞어 개선을 판정하거나 식사 메모만으로 변화 원인을 확정하지 않는다. 개인 맞춤 점심 추천, 사진 인식, 기기 연동, 미래 혈당 예측은 이번 준비본에 넣지 않았다.

## 어떤 작업을 했는가

### 1. 작업 폴더와 데이터 확인 환경 정리

프로젝트 폴더를 `cheezcyj/project-team4` 원격 저장소와 연결하고 데이터 확인용 Python 환경과 스크립트를 준비했다. `data`라는 폴더 이름은 유지하고 원본·추출본·메타데이터·가공본·문헌 사본의 위치를 구분했다. 로컬 데이터와 Python 환경은 Git 추적에서 제외했다.

SAS를 확인하기 위한 환경은 웹앱 실행 환경과 별개다. 이 폴더에 웹앱 프레임워크를 설치하거나 서비스 화면을 구현한 것으로 기록하지 않는다.

### 2. 처음 받은 CSV 묶음 점검

`data/csv.zip`을 읽어 행·칼럼 수, 결측치, 코드와 개인 ID의 연결, 영양소 합계의 일치 여부를 확인했다.

| 자료 | 확인한 크기 |
| --- | ---: |
| 2024 건강검진 개인별 CSV | 6,997행 × 17칼럼 |
| 2024 식품섭취 기록별 CSV | 543,782행 × 10칼럼 |
| 식품영양성분 핵심칼럼 CSV | 50,000행 × 13칼럼 |
| 2024 영양조사 코드자료집 | 4개 시트 |

섭취 기록의 개인 ID 6,802개는 모두 검진 자료와 연결됐다. 섭취 식품코드는 앞의 0을 보존해 5자리로 맞추면 조사 코드북과 연결되지만, 별도 영양성분 CSV의 식품코드와 정확히 일치하는 코드는 0개였다. 따라서 두 자료를 코드나 이름만으로 곧바로 합치지 않기로 했다.

섭취량과 일부 영양성분에는 결측이 많았다. 결측을 0으로 채우지 않고, g과 ml를 밀도 없이 바꾸지 않으며, 반복 행을 실제 중복 오류라고 단정해 삭제하지 않는 원칙을 세웠다. 이 수치와 제약은 최초 CSV 추출본에 대한 결과다.

결과: [데이터 점검](DATA_REVIEW.md), [구조화 프로필](data_profile.json), [점검 스크립트](../scripts/profile_data.py).

### 3. SAS 원본과 설명서 확인

2022~2024년 통합자료 `ALL`과 식품섭취자료 `24RC`, 총 6개 SAS 파일을 추출하고 행·변수 수·인코딩·파일 해시·한글 변수 설명을 기록했다. Python에서 필요한 변수만 읽는 예제를 작성했다.

제9기 원시자료 이용지침서와 연도별 영양조사 코드자료집도 확인했다. 조사 식품·음식코드의 의미, 검진 변수, 식품 중량, 복합표본 설계와 가중치 관련 위치를 정리했다. 모든 변수를 정제하거나 다년도 통합 분석을 완료한 상태는 아니다.

결과: [SAS 읽기 안내](SAS_GUIDE.md), [설명서 확인 기록](research/DATA_DOCUMENTS.md), `data/metadata/knhanes/`의 목록과 변수 사전.

### 4. 문헌과 데이터 출처 정리

혈당 기록·자가관리·입력과 조회의 사용성·지속 사용에 관한 공식 지침과 연구문헌을 조사했다. 문헌 정리에는 공식 지침·교육자료 2건과 논문 6편을 선별하고, 연구 결과와 이 프로젝트에 적용할 설계 제안을 구분했다.

이후 받은 질병관리청 교육자료, 대한당뇨병학회 진료지침 요약문과 국내 현황 자료도 관련 부분을 읽고 역할을 나눴다. 국내 현황 통계는 프로젝트 배경으로, 측정·식사·운동 자료는 챗봇 교육 내용의 근거로 정리했다.

출처 등록부에는 기관, 공식 관련 주소, 로컬 파일 해시, 버전과 확인 상태를 기록했다. 정확한 다운로드 주소나 입수일을 모르는 경우에는 미확인으로 남겼다. 기존 CSV의 제공기관명 확인과 실제 추출 경로 확인도 구분했다.

결과: [문헌 정리](research/DIABETES_LITERATURE_REVIEW.md), [문헌 등록부](research/references.json), [데이터 출처 등록부](research/DATA_SOURCES.md), [출처 JSON](research/data_sources.json).

### 5. 기획과 보드 논의에 맞춰 데이터 활용안 준비

공유된 기획 문서와 보드·UI 논의를 바탕으로, 로그인·기록 중심 기능에 어떤 데이터가 필요한지 검토했다. 챗봇이 모든 질문에 답한다고 약속하기보다, 본인 기록 요약·근거 있는 일반 지식·일반 운동 안내로 답변 범위를 구체화했다. 보드에 붙여 넣을 문안과 대표 질문 16개를 먼저 준비했다.

식품 자료는 처음 제공받은 CSV를 참고용으로 점검했으나, 공식 식약처 엑셀을 이미 보유했다는 설명을 반영해 음식·가공식품 엑셀을 주 전처리 원본으로 정정했다. 기존 CSV의 출처 복원이 공식 엑셀 작업의 선행 조건인 것처럼 다루지 않도록 했다.

최신 v5에 맞춘 준비본에서는 교육용 식단·운동 예시를 추가하고, 본인 기록 동의와 외부 AI 전송 동의, 중지·맥락 제거, 같은 측정 상황의 비교 기준을 반영했다. 사용자 혈당 CSV 가져오기와 식품 영양성분 CSV 가공은 서로 다른 작업으로 구분했다.

기존 기록: [데이터 활용안](research/CHATBOT_DATA_PLAN.md), [보드용 문안](research/FIGMA_DATA_BRIEF.md), [초기 16문항](research/CHATBOT_QUESTIONS.md). 최신 준비본은 아래 v5 항목으로 구분한다.

### 6. 시연용 가상 혈당 기록 준비

실제 환자나 조사 대상자를 앱 사용자로 바꾸지 않고, 가상 사용자 2명의 14일 범위 기록 67건을 만들었다. 누락 날짜, 다른 사용자, 나중에 저장한 기록, 한국 날짜 경계 등의 검증 사례 10개와 기대 결과를 준비했다.

이 자료에는 현재 ERD보다 넓은 실험용 필드가 있어 앱에 넣을 때 매핑이 필요하다. 생성한 가상 자료와 기대값의 일관성을 확인했으며, 실제 로그인·권한·DB·그래프·챗봇 응답이 통과했다는 의미는 아니다.

결과: [가상 기록 안내](DEMO_DATA.md), [기록 JSON](../fixtures/demo/glucose_records.json), [검증 사례](../fixtures/demo/scenarios.json).

### 7. 식품 데이터 가공과 조회 참고 코드 작성

| 자료 | 수행한 작업 | 현재 역할 |
| --- | --- | --- |
| 기존 영양성분 CSV 50,000행 | 전 행을 JSONL로 보존하고 검색·영양조회·같은 단위의 섭취량 환산 참고 코드 작성 | 기존 참고·검증용 자료 |
| 농촌진흥청 국가표준식품성분 DB 10.4 | 식품 3,366건의 코드 연계와 핵심 영양소 7개를 CSV·JSONL로 전처리 | 기본 식품·재료 조회용 별도 가공본 |
| 식약처 음식·가공식품 엑셀 | 보유 사실·출처·향후 역할 정리 | 전체 전처리 대기 |

식품성분표는 10.4판 시트와 해당 판의 코드 연계표를 연결했다. 가식부 100g 기준을 보존하고, 실제 0·미측정 `-`·미량 `Tr`·괄호의 인용/환산 표시를 구분했다. 원본 셀과 시트·행 위치도 남겼다. 다른 기관 DB와의 코드 대응까지 검증한 것은 아니다.

기록된 검증 결과에서 RDA 3,366행·핵심 성분 셀 23,562개를 원본과 대조했고, 검색·환산·표시·오류 처리 사례 18개가 통과했다. 기존 CSV 가공본과 원본은 보존했다.

결과: [기존 CSV 조회 자료](FOOD_DATA.md), [식품성분표 전처리 결과](FOOD_COMPOSITION.md), [RDA 처리 코드](../scripts/prepare_food_composition.py), `data/processed/`의 가공본과 검증 결과.

### 8. v5 챗봇 답변 자료 구조화

최신 기획에 맞춰 지식 요약 15개, FAQ 20개, 식단 예시 3개, 운동 안내 3개를 준비했다. 건강정보 PDF 4개, 식품성분 자료 1개, 제품 규칙 문서 3개를 출처로 연결하고 의학적 근거와 제품 규칙을 구분했다.

식단은 현미밥에 달걀·두부·생선과 채소를 조합한 교육용 예시다. 공식 기관이 제공한 완성 식단으로 표현하지 않았고, 개인별 섭취량·한 끼 총 열량·혈당 변화 효과를 정하지 않았다. 운동은 공식 자료의 걷기·실내 고정식 자전거·탄력 밴드 저항운동을 바탕으로 대상·주의사항·자료 링크를 작성했다.

개인 기록 답변에는 현재 ERD의 혈당값·측정 시각·측정 상황을 사용하도록 했다. 저장하지 않는 식사 시작 시각이나 아침·점심·저녁 구분을 있다고 가정하지 않았으며, 실제 수치를 넣을 자리는 조회·계산 결과용 자리표시자로 남겼다.

지식 JSON과 안내 문서를 생성하는 스크립트를 만들고, 개수·참조·페이지 범위·내용 해시·원본 해시·선택한 식품의 코드와 영양값·생성 문서 일치를 검사했다. 검증 보고서에 통과 결과가 남아 있다. 앱에서 실행할 DB seed나 실제 AI 응답 검증 결과는 아니다.

결과: [v5 준비본 안내](research/chatbot_v5/README.md), [FAQ 20개](research/chatbot_v5/FAQ_20.md), [식단·운동 카드](research/chatbot_v5/EXAMPLES.md), [지식 JSON](research/chatbot_v5/knowledge.json), [검증 보고서](research/chatbot_v5/validation_report.json).

## 현재 완료 범위와 남은 작업

지금까지 이 폴더에서 완료한 것은 **자료 확인, 활용 범위 판단, 출처 정리, 일부 식품 데이터 전처리, 가상 기록과 챗봇 답변 초안 준비**다. 기획 문서에 구현됐다고 적힌 기본 기능과, 이 작업 폴더에서 직접 구현·검증한 작업은 구분한다.

| 구분 | 상태 |
| --- | --- |
| CSV 품질 점검·SAS 읽기 환경·변수 목록 | 준비 완료 |
| 문헌·코드북·출처와 활용 제약 정리 | 검토 기록 작성 완료, 출처별 미확인 정보는 별도 표시 |
| 기존 CSV·RDA 10.4 가공본과 로컬 검증 | 준비 완료 |
| 가상 혈당 기록·기대 결과 | 준비 완료, 앱 적용 전 |
| v5 지식·FAQ·식단·운동 문안 | 초안과 일관성 검사 완료 |
| 식약처 음식·가공식품 엑셀 전체 전처리 | 미수행 |
| 앱·DB·실제 챗봇 연결 | 이 폴더에서 미수행 |
| 실제 접근 제어·동의 철회·외부 AI 전송·응급 대응 검증 | 미수행 |
| 챗봇 평가 40문항과 혈당 CSV 시험 12묶음 | 다음 준비 작업 |

PhysioNet CGMacros는 확장 분석 후보로 출처와 다운로드 상태를 기록했으나 현재 기능의 필수 데이터로 삼지 않았다. 본체 다운로드 완료와 분석 준비가 끝났다고 확인한 상태도 아니다. 과거 등록부의 다운로드 상태를 현재 상태로 단정하지 않는다.

다음 작업은 준비한 답변 자료를 기준으로 평가 질문과 기대 결과를 만들고, 앱에서 무엇을 확인해야 하는지 정하는 것이다. 자료 구조·계산의 일관성 확인과 실제 서비스 동작·의학적 내용·출처 이용조건 검토는 각각 구분해 진행해야 한다.
