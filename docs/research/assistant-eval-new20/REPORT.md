# 추가 20문항 평가와 공복 기록 요약

2026-10-22 기준. 기존 40문항을 그대로 보존하고 새로운 표현 20개를 첫 실행 전에 고정했다. 검색·응급 경계·설명 조건을 보완했고, 별도 동의를 받는 **최근 7일 공복 기록 요약**을 구현했다. 새 문항의 최종 자동 검사는 20/20, 원문 내용 검토는 18/20이다. 미충족 2개를 통과로 바꾸지 않았다.

## 구현한 기록 기능

도우미 안에서 기록 조회 동의를 체크한 뒤 **공복 기록 요약**을 누른다. 일반 AI 질문 동의와 구분하며 개인 기록을 모델에 보내지 않는다. 현재 서비스 동의가 있는 로그인 사용자만 이용할 수 있다.

- 한국시간 오늘 포함 7일 중 조회 시각까지 저장된 `fasting` 기록만 집계한다. 식전·기상 직후·식후·미래 시각·타인 기록은 제외한다.
- 측정 건수 기준 평균을 소수 첫째 자리까지 반올림하고 건수·최솟값·최댓값·기록 일수·미기록 일수를 보여준다. 같은 날 여러 측정도 각각 한 건이다.
- 기록이 없으면 평균·최솟값·최댓값은 `null`이다. 미기록일을 0으로 채우지 않는다.
- ‘본인 혈당 기록’을 출처로 표시하며 정상·호전·원인을 판단하지 않는다. 서버 계산 결과를 표시하는 첫 기능이며 AI가 개인 기록을 해석한 결과가 아니다.
- 기록 동의는 이번 요청에 적용한다. 체크 해제·닫기·이동·로그아웃·계정 변경 시 진행 요청과 화면 내용을 지운다. 앱에서 기록 저장·수정·삭제·가져오기 시 같은 탭과 다른 탭의 이전 요약도 무효화한다.

API·계산·동의의 자세한 계약은 [도우미 구현 문서](../../ASSISTANT.md#최근-7일-공복-기록-요약)에 있다. 실제 Supabase 배포에 대한 E2E 검증은 하지 않았으며, 실제 API 검사는 새 파일을 쓰는 격리된 로컬 데모 저장소로 실행했다. 요청별 동의는 지속적인 서버 권한 부여·철회 이력을 대신하지 않는다.

자동 검사는 HTTP·분류·응답 형태·출처 ID와 서버 출처 메타데이터를 검사한다. 내용 평가는 개발자가 답변 원문을 고정 `must/must_not`과 비교한 단회 검토다. 새로운 20개도 기존 지식과 경계를 아는 개발자가 작성했으므로 외부 독립 평가나 의료 전문가 승인이 아니다.

최초 T10은 ‘혈당 숫자’라는 표현으로 운동 허가 한계 지식을 검색하지 못했다. 같은 뜻의 ‘혈당 수치’를 검색어에 보태고 운동 문맥 조건은 유지했다. T18은 예문과 실제 현재 증상이 한 문장에 섞이자 전체 문장을 설명 요청으로 제외했다. 일부 대조 연결어로 절을 나눠 현재 보고를 다시 확인한다. 이 보완이 모든 인용·부정·변형 표현을 처리한다는 뜻은 아니다.

T05의 중간 답변은 100mL당 수치를 실제 총 mL 숫자로 곱하라고 설명했다. 표시 기준량으로 나누는 과정이 빠진 잘못된 표현이다. 중간 원문을 보존하고 환산 설명을 보완했다. 최종에서는 표시 기준량과 실제 양을 함께 확인하도록 답했으며, 용량이 없는 상태에서 총 영양값을 생성하지 않았다. 제품별 영양 DB 조회·섭취량 계산 도구를 구현한 것은 아니다.

## 남은 2개와 평가 범위 차이

T08·T09는 개인 운동 제한과 기구 사용법·자세를 확인하라고 답했지만, 고정 문항이 요구한 **기구·의자의 안정성 확인**을 명시하지 않았다. 현재 연결된 X02 요약과 조건도 사용법·자세를 요구하며 이 추가 항목을 명시하지 않는다. 따라서 내용 점수는 미충족으로 유지하고, 이를 의료 오류로 확정하거나 현재 근거에 없는 문구를 추가하지 않았다.

다음 작업은 해당 기구 안내의 근거 범위를 확인하여 지식과 평가 기준을 함께 정리하는 것이다. 기존 문항을 수정한다면 새 평가 버전에서 변경 이유를 기록하고, 이 20개와 최초 결과는 그대로 보존한다. T07처럼 질문과 직접 관계없는 영양표시 설명을 덧붙이는 문체 문제도 일부 남아 있다.

## 실행·소프트웨어 검증 증거

기존 로컬 모델 `gemma-4-e4b-it-qat`를 사용했고 모델 로드·설정 변경은 하지 않았다. 앱은 127.0.0.1:3000, 모델의 호환 API는 127.0.0.1:1234/v1을 사용했다. 각 실행의 `run.json`에 빌드 ID·문항/러너/소스 해시·설정 중 비밀이 아닌 항목·질문별 HTTP 원문·지연·자동 검사를 기록했다. 모델 목록에는 구성한 모델만 남긴다. 런타임 모델의 가중치·설정을 원격 증명한 것은 아니다.

`run.json`의 내용 검토 상태는 최초 캡처의 `pending`을 유지하며, 이후 판정은 `review.json`에 해당 run의 SHA-256과 함께 분리했다. 소스 스냅샷·러너 원문·문항 해시를 검증했다. 일부 초기 소스 스냅샷은 기록된 해시와 일치하는 Git/보존 버전으로 복원했다.

- [전체 검사 로그](runs/20261022-release/verification/check-release.log): lint·타입·단위 65개·SQL 70/62개·계정 삭제 18개·프로덕션 빌드 통과.
- [공복 요약 실제 API·브라우저 5개](runs/20261022-release/verification/summary-e2e-release.log): 인증·Origin·서비스/기록 동의·타인 격리·정확한 집계·빈 기록·동의 해제 중 늦은 응답 차단·다른 탭 기록 변경·로그아웃 초기화 통과. 모델 호출 없이 새 가상 데이터 파일로 실행했다.
