## 개인 기록과 일반 질문의 분리

계정 A의 공복 기록 110·130과 계정 B의 250을 만들었다. A의 요약은 **2건, 평균 120, 최소 110, 최대 130**이었다. A로 B의 기록을 직접 요청하면 404였다. 다른 탭에서 130을 140으로 수정하자 이전 도우미가 닫혔고, 새 요약은 **2건, 평균 125**였다. 이 요약 과정에서 모델 요청은 없었다.

모델 경계 프록시는 계정 ID·이메일·시험 기록 ID·시험 메모의 포함 여부를 확인했다. 전체 7개 요청을 사후 대조해 사용자 프롬프트의 최상위 키가 `question`, `knowledge`뿐이고, 선택한 지식의 제목·주제·요약·조건이 현재 자료집과 일치하는 것도 확인했다. 개인 기록 객체나 요약 통계는 프롬프트에 넣지 않았다. 현재 질문에 사용자가 직접 쓴 내용은 모델 입력 대상이므로, 이 결과를 임의 민감정보 자동 제거의 보장으로 해석하지 않는다.

두 성공 실행(mock-03, live-01)은 각각 자신이 만든 기록 3개를 모두 삭제했다. 뒤이은 프로덕션 검사에서도 A의 최근 공복 기록은 0건이었다. 기존 계정은 유지했다.

## 모델 엔진 오류와 집계

공급자 HTTP 요청은 **7회**, 성공한 생성 응답은 **4회(HTTP 200)**다. 나머지 3회는 다음 HTTP 400 오류였다.

```json
{"error":"Engine protocol predict request failed: fetch failed"}
```

G02·G03·G04에서 각각 첫 시도가 이 오류를 반환했고 앱의 기존 특정 오류 재시도 뒤 성공했다. 러너가 질문을 재실행하거나 일반 오류를 임의로 재시도하지 않았다. 엔진 내부 원인은 확인하지 못했다. 이를 성공한 추론 7회나 생성 답변 8개로 기록하지 않는다. 최종 자료 요약 보충은 1개다. 토큰 속도·동시 사용자 성능·장시간 안정성은 측정하지 않았다.

## 승인 차단과 거절 동작 확인

기본 Supabase 앱은 평가 전후 초안 일반 답변을 제공하지 않는다. 임시 개발 평가 앱은 개발 모드·실제 loopback URL/Host·현재 서비스 동의·`.invalid` 계정·서버 UUID 허용 목록을 모두 요구했다. 비허용 계정은 503, 비로그인은 401, AI 처리 미동의와 다른 Origin은 403, 본문의 `user_id`·`loopbackRequest` 추가는 422였다. 기록 조회 동의가 없으면 요약은 403이었다. 이 검사에서는 모델 요청이 없었다.

별도 프로덕션 빌드에서도 **평가 옵션과 A의 허용 목록을 일부러 켜고** 실제 인증 요청을 보냈다. 일반 답변 상태는 `available=false`, `draftPreview=false`, POST는 503이었고, 기록 요약은 사용 가능했다. 모델 호출은 0회, DB 변경은 없었다. [프로덕션 검사 원본](runs/20261023-local-supabase/production-gate.json)을 보존했다.

초기 모의 실행 2회는 질문·기록 생성 전에 허용 계정 상태 확인에서 실패했다. Next가 내부 URL을 `localhost`로 만들고 브라우저 Host는 `127.0.0.1`인 차이였다. 두 호스트가 모두 literal loopback이고 포트가 같음을 확인하고, Origin은 실제 Host 기준으로 대조하도록 수정했다. 외부 Host·다른 포트·cross-site·전달 헤더 위조를 허용하지 않는 단위 검사를 추가했다. 일시적인 진단 출력은 성공 실행 전에 제거했다. 실패 실행도 별도로 보존했다.

## 회귀 검사와 남은 범위

- 단위 테스트 **72개 통과**. 평가 허용 조건의 실패 조합, 요청 주소 검증, 본문 위조, 모델 입력 분리를 포함한다.
- 모델 비활성 상태의 기록 요약 브라우저 회귀 **6개 통과**. 권한·본인 범위·정확한 계산·동의 철회·다른 탭 수정/로그아웃·수정/재분류/삭제 후 갱신을 확인했다. 이 6개는 demo 저장소를 사용하는 별도 회귀이며 hosted DB 검사와 구분한다.
- lint·타입 검사·격리 프로덕션 빌드 통과. 빌드 산출물은 `.local/assistant-supabase-eval-build`를 사용했다.
- 평가용 Next가 생성한 설정 경로와 AGENTS 파일은 원본을 로컬에 보존한 뒤 작업 전 상태와 대조해 복구했다. 기본 앱 설정·README·마이그레이션은 이번 작업에서 변경하지 않았다. 임시 앱과 프록시는 종료했다.

이 평가는 기존 40문항 전체 재실행이 아니다. 실제 사용자의 건강정보를 넣지 않았으며, 개인 수치 해석·자유 질문 기반 DB 도구 선택·기간 비교는 여전히 미지원이다. 키워드 검색과 제한적인 위험 표현 규칙의 한계, 자료의 초안 승인 상태도 유지된다. 다음 기능 확장은 별도 범위·동의·검증 기준을 먼저 정해야 한다.
