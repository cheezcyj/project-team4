# 챗봇·식품 조회 데이터 준비 정리

정리일: 2026-10-21 · 팀 3명 · 제출: 2026-10-26 10:00 KST

이 문서는 최근 대화와 직전 Figma 검토를 바탕으로 만든 **데이터 준비 초안**이다. 팀의 최종 기능 확정이나 앱 구현 완료를 뜻하지 않는다. 기존 `PROJECT_PLAN.md`와 `DATA_REVIEW.md`의 개정 1.2 기준 기능 범위는 과거 기록으로 남긴다.

## 1. 이번에 준비한 범위

대표 질문 16개를 [질문·답변 근거 목록](CHATBOT_QUESTIONS.md)에 정리했다. 출처·파일 해시·페이지·답변 조건은 [구조화 JSON](chatbot_knowledge.json)에 함께 보관한다. JSON은 검토와 후속 구현을 위한 자료이며 실행 중인 챗봇 DB는 아니다.

| 질문 유형 | 사용할 데이터 | 답변 방법 | 준비 상태 |
| --- | --- | --- | --- |

| 30분 동안 할 가벼운 운동 | 질병관리청 운동요법, 학회 지침의 운동 부분 | 일반적인 운동 선택지를 설명하고 적용 조건 확인 | 후보·주의 조건 정리, 개인 운동 처방은 별도 |

점심 메뉴 추천은 뒤로 미룬다. 사진 인식, 기기 자동 연동, 식사에 따른 미래 혈당 예측도 이번 자료 준비 범위에서 제외한다.

**자료의 날짜를 구분한다.** 질병관리청 웹페이지의 업데이트는 당뇨병 2026-09-16, 운동요법 2026-07-31, 식이요법 2026-08-04로 확인했다. PDF의 2026-10-21은 브라우저 인쇄일이다. 웹페이지 업데이트 날짜가 본문 모든 수치의 근거연도를 바꾸는 것은 아니다.

학회 진료지침은 2025판이며, 공식 게시물의 수정 이력에는 2025-12-01 운동 전 혈당 대처·약물 표 오기 수정, 2026-02-12 인슐린 펜 교육영상 QR/URL 수정이 명시되어 있다. 파일명에 2026년이 있어도 전체 임상 권고가 2026년에 개정됐다고 쓰지 않는다.

Fact Sheet는 2026년 발간 자료지만 주요 현황 수치는 **2023-2024년 통합 조사**다. 30세 이상 유병률 16.3%는 당화혈색소를 포함한 정의이며, 같은 도표의 공복혈당 기준 15.3%와 구분한다. 조절률 38.7%는 30세 이상 **당뇨병 유병자 중** 당화혈색소 6.5% 미만인 비율이다. 이 통계 정의를 모든 앱 사용자의 개인 목표로 적용하지 않는다.

### 지식 문장으로 옮길 때의 기준

- 페이지 전체를 무조건 넣기보다, 질문에 필요한 단락·표 제목·대상 조건을 함께 선정한다. 두 쪽 펼침 표는 텍스트 추출만으로 열 순서를 확정하지 않는다.
- 질병관리청 당뇨병 PDF에는 이전 연도 지침을 인용한 수치가 있고, 식이요법 PDF에도 운동·저혈당 관련 설명이 섞여 있다. 운동 전 혈당별 대처와 인슐린 용량 같은 수치 규칙은 이번 초안에서 자동 답변 규칙으로 만들지 않는다. 후속 검토 시 학회 수정본의 해당 표와 대상 조건을 대조한다.
- 기본 지식·운동 답변에도 출처와 적용 범위를 붙인다. 통계, 일반 교육, 개인 기록 요약을 구분한다.
- 공식 공개 자료라도 원문·도표·이미지의 서비스 재사용 조건은 따로 확인한다. 현재는 짧은 자체 요약과 원문 링크를 정리했으며, PDF 전체 재배포 승인을 확인한 상태는 아니다.

## 3. 현재 UI 흐름에 맞춘 최소 데이터

직전 확인한 Figma 설계는 **혈당 수치 → 측정 상황 → 선택적 식사 메모·음식 검색 → 최종 확인·측정 일시 편집 → 저장 완료** 흐름이다. 사진 첨부 UI가 있어도 사진을 해석하는 기능이 구현됐다는 뜻은 아니다.

다음은 후속 개발을 위한 필드 제안이며 기존 ERD를 수정한 것은 아니다.

| 데이터 | 최소 필드 제안 | 입력 부담을 줄이는 방법 |
| --- | --- | --- |
| 혈당 기록 | 기록 ID, 사용자 ID, 혈당값, 단위, 실제 측정 일시, 시간대, 측정 상황, 생성·수정 시각 | 단위 mg/dL 표시, 측정 일시는 현재 시각 기본값과 수정 가능 UI. 저장 시각과 실제 측정 시각은 분리 |
| 측정 상황 | 공복/식전/식후 1시간/식후 2시간/취침 전/기타 등 의미가 분리된 코드 | 아침·점심·저녁 같은 식사 구분과 공복·식전·식후 같은 측정 조건을 별도 보관. 기존 UI 선택지를 정규화해 팀과 확정 |
| 식사 메모 | 기록 ID, 자유 메모 | 선택 입력. 메모만으로 음식 코드나 먹은 양을 확정하지 않음 |
| 선택한 음식 | 기록 ID, 식품코드, 표시 이름, 기준량·단위, 영양정보 출처·버전 | 검색 결과를 고르면 영양정보를 자동으로 연결. 한 기록에 여러 음식 선택 가능 여부는 팀과 확정 |
| 섭취량 | 음식별 양·단위, 입력 여부 | 선택 입력. 없으면 기준량 영양정보만 제공. 실제 섭취량 계산을 원할 때만 추가 질문 |

식사 메모의 음식명만으로는 정확한 영양 합계가 나오지 않는다. **음식 선택 + 확인된 섭취량**이 있을 때 그 음식의 섭취량 기준 계산이 가능하다. 선택되지 않은 음식이 있거나 양이 빠지면 이를 하루 총섭취량으로 표시하지 않는다.

## 4. 식품 DB 정리 규칙

**원본 선택 정정(2026-10-21):** 식약처 공식 배포 엑셀이 이미 제공됐다는 사용자 확인을 반영해 `20260828_음식DB_19617건.xlsx`와 `20260929_가공식품DB_323197건.xlsx`를 주 전처리 원본으로 삼는다. 추가 다운로드나 기존 CSV의 추출 경로 복원이 선행 조건은 아니다. 식품성분표 엑셀은 원재료 보완용으로 점검하고, 건강기능식품은 별도 보관하며, 수산식품 PDF는 참고 자료로 둔다.

식품성분표는 10.4판 3,366건을 별도 전처리했다. 가식부 100g 기준 핵심 영양소 7개와 미측정·미량·인용/환산 표시를 보존하고, 엑셀 내부의 식품코드 연계표와 전수 대조했다. [결과·재현 방법](../FOOD_COMPOSITION.md). 식약처 엑셀과의 코드 대응·자동 병합을 수행한 것은 아니다.

아래 점검 결과는 `data/csv.zip` 안의 `식품영양성분_핵심컬럼.csv`를 대상으로 한 기존 참고본이다. [기존 프로필](../data_profile.json)의 ZIP 해시와 현재 원본이 일치함을 확인했다. **5만 행은 현재 로컬 추출본의 크기**이며 공식 엑셀 전체의 크기·통계가 아니다. 식약처 엑셀 기반 가공본으로의 교체는 아직 수행하지 않았다.

| 확인 항목 | 현재 결과 | 적용 |
| --- | --- | --- |
| 행·식별자 | 50,000행, 식품코드 50,000개, 완전 중복 0행 | 식품코드는 문자열로 보존 |
| 기준량 | 100g 40,653행 / 100ml 9,347행 | 항상 기준량과 단위를 함께 표시 |
| 구분 | 음식 17,732행 / 가공식품 32,268행 | 검색 결과에서 구분 표시 |
| 공급기관 칼럼 | 모두 식품의약품안전처 | 공공데이터포털 입수 경로와 제공기관을 구분 |
| 빈칸 | 지방 11,684 / 탄수화물 11,158 / 당류 123 / 식이섬유 44,793 / 나트륨 63 / 식품중량 1,895 | 없는 값은 `정보 없음`으로 처리. 0으로 채우지 않음 |

조회에 쓸 원본 칼럼은 `식품코드`, `식품명`, `데이터구분명`, `영양성분함량기준량`, `에너지(kcal)`, `탄수화물(g)`, `당류(g)`, `단백질(g)`, `지방(g)`, `식이섬유(g)`, `나트륨(mg)`, `식품중량`, `제공기관명`의 13개다.

계산은 같은 차원에서만 한다. 예를 들어 기준이 100g이고 섭취량이 200g이면 있는 성분 값에 2를 곱한다. 100ml 자료에 200g을 입력하면 밀도 정보 없이 환산하지 않는다. `식품중량`을 검증 없이 1인분·1공기의 양으로 간주하지 않는다. 음식 이름이 같아도 조리법·제품이 다르면 검색 결과에서 선택하게 한다.

공식 보완 경로는 [식약처 식품영양성분 API](https://www.data.go.kr/data/15127578/openapi.do), [전국통합식품영양성분정보 표준데이터](https://www.data.go.kr/data/15100064/standard.do), [식품영양성분 DB API 안내](https://various.foodsafetykorea.go.kr/nutrient/industry/openApi/info.do)다. 이 링크들은 보완·검증 경로이며 현재 ZIP의 정확한 다운로드 URL로 확인한 것은 아니다. 추출 시점·필터·원본 상세 URL·이용조건은 보완해야 한다.

국민건강영양조사 섭취기록의 `N_FCODE`와 이 식품 DB 코드는 서로 다른 체계이고 기존 점검에서 정확 일치가 없었다. 이름만 보고 조인하지 않는다. `NF_CHO` 등은 해당 섭취기록의 영양 기여량이므로 100g당 성분으로 취급해 다시 환산하지 않는다.

## 5. 개인 혈당 질문의 집계 기준 초안

1. 로그인한 본인의 기록만 조회한다. 챗봇이 사용자 ID나 접근 범위를 임의로 정하지 않게 한다.
2. 실제 측정 일시를 사용하고 한국 시연 기준은 `Asia/Seoul`로 둔다. 날짜 경계는 해당 시간대의 00:00부터 다음 날 00:00 직전까지다. 기본 기간 제안은 최근 7일=오늘 포함 7개 달력 날짜이며 오늘은 현재까지의 부분 기록임을 표시한다.
3. 공복끼리, 같은 식사의 식후 2시간끼리처럼 측정 조건을 맞춘다. 조건이 불분명한 기록은 별도로 표시한다. 어제 식전과 오늘 식후를 섞은 평균으로 건강이 좋아졌다고 판단하지 않는다.
4. 같은 조건 안에서 건수·기록값·평균·차이를 프로그램이 계산한다. 평균은 해당 조건의 기록별 산술평균으로 명시한다. 날짜별 기록 수 차이도 함께 보여 준다.
5. 한쪽 날짜가 비었으면 변화량을 만들지 않는다. 1건씩 있으면 두 측정값의 차이로 표현하며 추세·개선으로 확대하지 않는다. 일부 날짜가 비어도 확인된 기록만 요약하고 누락 날짜를 알린다.
6. 챗봇은 계산 결과를 설명한다. 식사·운동 때문에 변했다는 인과 설명, 수기 기록만으로 계산한 CGM 시간범위 지표, 혈당 평균으로 추정한 당화혈색소는 제공하지 않는다.

예시 검증용 가상 기록: 어제 공복 120, 오늘 공복 110 mg/dL이면 차이는 -10 mg/dL이다. 오늘 식후 180 mg/dL이 추가돼도 공복 비교 결과는 바뀌지 않아야 한다. 이 예시는 실제 사용자 기록이 아니다.

## 6. 추가 수집보다 먼저 할 작업

후속 작업(2026-10-21): [출처 등록부](DATA_SOURCES.md)를 작성하고, [가상 기록 67건·검증용 사례 10개](../DEMO_DATA.md)를 준비했다. 아래 표의 앱 응답 확인은 실제 앱 연결 후 수행할 작업이다.

식품 검색 준비: [식품성분표 10.4 전처리](../FOOD_COMPOSITION.md)에 기본 식품 3,366건 CSV·JSONL과 검색·조회·환산 검증 결과를 정리했다. [기존 전달 자료](../FOOD_DATA.md)의 CSV 기반 5만 행 참고본은 보존했다. 식약처 음식·가공식품 엑셀 전처리는 별도 후속 작업이다.

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 팀과 첫 시연 질문 선택 | 기록 비교·음식 조회·기본 지식 중 먼저 연결할 질문 ID 결정. 운동은 일반 안내 범위 확인 |
| 2 | 보유한 공식 엑셀로 식품 조회용 추출본 만들기 | 파일별 머리글 대응, 문자열 식품코드, 기준량·단위·결측·출처 보존. 중복과 대표 검색어 확인 |
| 3 | 공식 엑셀의 배포 메타데이터 보완 | 공식 배포 출처는 사용자 확인 기록 완료. 파일별 상세 페이지·실제 입수일·이용조건 보완 |
| 4 | 질문별 지식 단락 준비 | 이 문서의 페이지에서 짧은 요약·대상 조건·원문 링크를 보존. 숫자 처방 규칙은 검토 전 제외 |
| 5 | 가상 기록으로 응답 확인 | 비교 조건 차이, 누락 기록, 음식 동명이름, 단위 불일치, 성분 결측에서 기대 답변 확인 |
| 6 | 필요한 보완 자료 점검 | 식품성분표 10.4 핵심 성분 전처리는 완료. 추가 성분 정규화나 수산식품 PDF 검토는 필요할 때 수행 |

**현재 더 큰 데이터셋을 찾는 것이 우선은 아니다.** 대표 질문을 시연할 자료는 확보했다. 사용자 기록은 앱에서 생성해야 하고, 식품 출처 메타데이터와 답변용 지식 단락을 준비하는 일이 남았다. 조회·집계 코드는 이번 문서 정리에서 구현하지 않았다.

식품성분표 10.4의 핵심 성분·내부 코드 연결은 전수 대조했다. 식약처 엑셀·수산식품 PDF의 전체 내용·출처 간 코드 대응은 아직 검증하지 않았다. 음식 엑셀의 흑미밥 3개 코드는 기존 CSV와 기준량·식품중량이 일치함을 확인했으며, 상세 결과는 [전달 자료](../FOOD_DATA.md)에 기록했다. 국민건강영양조사와 영양조사 코드자료집은 집단 통계·변수 해석용으로 보존하며 현재 챗봇 개인 기록 조회의 원천으로 쓰지 않는다.

### 후속 구현에서 한 번에 확인할 사례

- 다른 사용자의 기록이 조회되지 않는가? 저장 시각 대신 실제 측정 시각으로 분류되는가?
- 어제·오늘의 측정 조건이 다르거나 한쪽 기록이 없을 때 비교를 보류하는가?
- 오늘이 아직 끝나지 않았고 날짜별 기록 수가 달라도 건수·기간을 밝히는가?
- 같은 이름의 여러 식품, 식품 미검색, 섭취량 미입력, g/ml 불일치, 결측 영양소를 구분하는가?
- 선택한 음식 일부만 계산하고 이를 하루 전체 섭취량으로 표현하지 않는가?
- 운동 질문에서 증상·제약이 불명확할 때 개인 운동 허가나 약물 용량 변경을 답하지 않는가?
- 답변 출처의 연도·페이지·통계 분모가 유지되는가? 근거가 없는 질문에는 답변 범위를 알리는가?

## 7. 보드 공유용 문안

> **데이터 활용 방향 / 김승진**
>
> 사용자 혈당 기록은 같은 측정 상황끼리 어제·오늘 또는 최근 7일을 비교하는 데 활용하려고 합니다. 음식은 텍스트로 검색해 선택하면 공공 식품 DB의 영양정보를 연결하고, 먹은 양이 입력된 경우에만 섭취량 기준으로 계산하는 방향을 제안합니다.
>
> 챗봇의 기본 당뇨 지식과 가벼운 운동 안내는 질병관리청 자료와 대한당뇨병학회 진료지침을 근거로 준비했습니다. 질문별로 사용할 페이지와 답변 조건을 정리했고, 개인 기록이 없거나 음식·양이 불분명하면 확인된 범위만 답하도록 하려고 합니다.
>
> Diabetes Fact Sheet 2026은 서비스 필요성을 설명하는 국내 현황 근거로 활용할 수 있습니다. 점심 메뉴 추천은 후순위로 두고, 우선 기록 비교·음식 영양정보·기본 지식 질문부터 팀과 시연 범위를 정하면 될 것 같습니다.
