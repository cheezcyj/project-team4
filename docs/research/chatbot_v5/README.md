# 챗봇 데이터 준비본 — v5

기획 문서 개정 5.0에 맞춰 작성한 **지식 요약 15개·FAQ 20개·식단 예시 3개·운동 안내 3개**입니다. 기존 16문항 초안은 보존했습니다. 앱·DB·Figma에 반영하거나 실제 AI 응답을 실행한 상태는 아닙니다.

이 준비본은 당시 기획 문서 기준입니다. 이후 확인한 원격 MVP에는 측정 상황 10개·식사 시간대·별도 식사 기록이 구현되어 있으므로, 앱에 연결하기 전 [실제 코드와의 차이](../MVP_CODE_AND_MODEL_REVIEW.md#기존-데이터-준비본과-맞춰야-할-차이)를 반영해야 합니다.

먼저 [식단·운동 카드 문안](EXAMPLES.md)을 보면 화면에 제시할 내용을 확인할 수 있습니다. 전체 질문과 답변 조건은 [FAQ 20개](FAQ_20.md), 근거 목록은 [출처 정리](SOURCES.md), 개발 전달용 원본은 [knowledge.json](knowledge.json)에 있습니다. [검증 결과](validation_report.json)는 파일과 데이터의 일관성을 확인한 기록입니다.

식단은 공식 기관이 제공한 완성 식단을 옮긴 것이 아닙니다. 공식 자료의 식품군 구성 원칙을 바탕으로 작성한 교육용 조합입니다. 개인별 분량이나 한 끼 영양 합계·치료 효과를 제시하지 않습니다. 운동도 시간·강도·반복 횟수를 임의로 처방하지 않습니다. 개인 맞춤 점심 추천은 이 준비본에 포함하지 않았습니다.

개인 기록 문항은 `glucose_mg_dl`, `measured_at`, `measurement_context`, 선택 항목인 `meal_memo`라는 현재 v5 ERD의 범위에 맞췄습니다. 다만 식사 메모 원문 조회는 이번 FAQ에 넣지 않았습니다. 아침·점심·저녁 구분, 식사 시작 시각, 선택한 음식이나 실제 섭취량을 DB에 저장한다고 가정하지 않습니다. 개인 기록값은 이 공통 지식 파일에 포함하지 않았습니다.

## JSON을 사용하는 방법

- `sources`: 건강정보 PDF 4개·식품성분 자료 1개·제품 문서 3개. 공식 URL, 로컬 파일 해시, 날짜 구분, 확인 상태를 기록했습니다. 제품 문서는 의학적 근거와 구분합니다.
- `knowledge_entries`: 일반 지식 요약 15개. 검색어, 적용 조건, 근거 자료와 PDF 페이지, 내용 해시가 있습니다.
- `faqs`: 질문 20개와 답변 틀, 연결 지식, 필요한 입력, 정보 부족 시 처리입니다. 개인 기록 문항의 `operation`은 구현할 동작의 이름이며 실행 함수가 아닙니다. `{...}`는 코드가 조회·계산한 결과를 넣는 자리입니다.
- `meal_examples`: 식단 카드와 재료별 식품 코드, **가식부 100g 기준** 핵심 영양소 7개 및 원본의 미측정·미량·인용/환산 표시를 보존했습니다. `amount_g`, `total_nutrition`은 의도적으로 `null`입니다.
- `exercise_examples`: 운동 카드와 대상·단계·주의사항·근거입니다. 개인별 시간·강도·반복 횟수는 `null`입니다.
- `record_contract`·`policy`: 본인 계정·동의 범위, 집계 방식, 외부 전송, 거절·중지 기준입니다. 서버와 DB에서 구현·검증해야 하는 기준입니다.

이 JSON은 **준비본 자체의 스키마**이며 ERD에 바로 넣을 SQL seed가 아닙니다. 지식의 `id`는 문항용 식별자이고 `version`은 각 요약의 초안 버전입니다. ERD의 자료별 버전 유일성 `(source_id, version)`에 그대로 매핑하면 충돌하므로, DB 반영 시에는 출처별 문서로 묶어 버전을 부여하거나 지식 식별 구조를 먼저 맞춰야 합니다.

`approved_at`·`review_due_at`은 정하지 않았고 `runtime_publishable`은 `false`입니다. 출처 이용조건과 내용 검토, 승인 및 재검토 기한을 정한 뒤 앱에 반영해야 합니다. 원본 전체 저장·재배포·외부 AI 전송의 허락을 이 준비본이 대신하지 않습니다. RDA 자료는 원본 설명문의 공공누리 제1유형과 필요한 출처표시를 별도로 기록했습니다.

## 재현과 검증

별도 패키지 없이 Python 3.10 이상에서 실행합니다. JSON이 작성 원본이며 Markdown 세 파일은 생성 결과입니다. 내용을 바꾸려면 JSON을 수정하고 해당 지식의 내용 해시를 갱신한 뒤 문서를 다시 생성합니다. 내용 해시는 `version`, `topic`, `language`, `title`, `summary`, `keywords`, `evidence`, `conditions`를 키 정렬한 공백 없는 UTF-8 JSON의 SHA-256입니다.

```powershell
python scripts/prepare_chatbot_v5.py
```

기본 명령은 개수·식별자·참조·페이지 범위·내용 해시·답변 자리표시자·결측 표시와 생성 문서의 일치를 검사합니다. 로컬 원본 자료가 있는 이 작업 폴더에서는 다음 명령으로 원본 8개와 RDA 가공본의 해시, 선택한 재료의 코드·이름·기준량·영양값·원본 표시까지 대조합니다.

```powershell
python scripts/prepare_chatbot_v5.py --verify-local --report docs/research/chatbot_v5/validation_report.json
```

JSON 수정 후 Markdown 재생성:

```powershell
python scripts/prepare_chatbot_v5.py --write --verify-local --report docs/research/chatbot_v5/validation_report.json
```

원본 `data/`와 문서 검토 스냅샷 `.tmp/research/`는 Git에서 제외돼 있어 다른 PC에서는 로컬 원본 대조를 바로 실행할 수 없습니다. 기본 구조·문서 일치 검사는 원본 없이 가능합니다. 이 검사 결과는 의학적 내용 승인이나 실제 챗봇 품질·접근 제어 검증을 뜻하지 않습니다.
