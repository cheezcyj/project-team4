# Ollama 최종 보완과 1차 MVP 확인

무가당 답변에서 수치·기준 단위가 빠져도 ‘함량 기준’이라는 표현만으로 통과하던 검사를 수정했다. 실제 인용한 N03 자료의 **100g·100mL·0.5g 미만** 조건을 각각 확인하고, 누락 시 기존 출처 요약으로 대체한다. 새 수치나 미인용 자료를 생성해 보충하지 않는다.

2026-10-23, 회원가입 수정이 제외된 PR 대상 코드만 별도 작업 폴더에 구성하여 확인했다. **고정 40문항 자동 검사 40/40, 기존 전제 변경 2개를 제외한 내용 검토 38/38**이다. 이전 질문·필수/금지 기준·자료집 승인 상태는 바꾸지 않았다. [원문과 항목별 판정](runs/20261023-ollama-final/RESPONSES.md), [검토 JSON](runs/20261023-ollama-final/review.json), [실행·모델 요청 기록](runs/20261023-ollama-final/)을 보존했다.

## 세 가지 확인

| 항목 | 결과 |
| --- | --- |
| 누락 보완 | Ollama에서 관찰한 원문, 수치·단위 누락, 잘못된 기준값·이하 표현에 대한 회귀 검사 통과. 완전한 원문·공백·단위 대소문자·전각 숫자는 불필요한 대체 없이 유지 |
| Ollama 재평가 | 자동 40/40, 내용 38/38. 모델을 내린 뒤 첫 실제 앱 요청 HTTP 200, **3,158ms** |
| 팀 시연 준비 | PR 코드의 프로덕션 demo를 3007에서 실행하고 360px 화면의 답변·출처 확인. 별도 실제 Supabase Auth·DB 평가 8문항·5개 시나리오 묶음 통과. [팀 실행·자료 상태 안내](../../ASSISTANT_TEAM_SETUP.md) 작성 |

다른 팀 PC나 운영 배포 환경에 접속해 실행한 결과는 아니다. 동일 PC에서 PR 대상 코드와 문서의 실행 경로를 확인한 것이다. 현재 자료집은 미승인 초안이며 기본 Supabase 앱의 일반 답변 차단을 유지한다. 팀의 내용·출처 검토나 실제 이용자 대상 공개 승인을 이 시험으로 대체하지 않는다.

## 모델·자료 조건

- Ollama `0.40.9`, `127.0.0.1:11434`, 로컬 별칭 `team4-gemma4-e4b-qat:latest`.
- 모델 digest `edccf9a100bae46f416d009b2b55866edd916366b6fc7683817277b46f339a35`, context 131072, 기존 **1슬롯** 유지. Ollama 앱·서버 재시작이나 사용자 환경변수 변경 없음.
- 기존 GGUF와 가져온 blob의 SHA-256 `676c35070db6dbe52f93e9c864ee0fba4eddea94b9c875d9cb10daff453fbaee`는 앞선 연결 검증과 동일하다. 모델 다운로드·재양자화·교체 없음.
- temperature 0.1, max_tokens 512, thinking false, reasoning none, 응답 형식 text. 모델 어댑터·생성 프롬프트는 이번 누락 보완에서 변경하지 않았다.
- 자료집 `replacement-v1-draft-3`, SHA-256 `2fe0ec8e766a480fdb90000c413a598b1b0e02beb82edf18de766ee3f74df8da`; 문항 SHA-256 `13f05acb68e6e7c5db5f491b857a916e8178cc5f5717335867a63510374419bd`. 내용·해시·승인 상태 유지.

빌드·실행 소스는 평가 폴더의 사본과 해시로 식별한다. 일반 앱의 환경 파일은 초안 미리보기 0을 유지하고, demo 자식 프로세스에만 미리보기 1을 지정했다. `run.json`의 환경 파일 스냅샷과 실제 앱의 `draftPreview=true`가 다른 이유다. 모델 요청은 임시 loopback 감사 프록시 11482를 거쳐 동일한 Ollama로 전달했다.

## 40문항 내용 검토

모델 요청은 **17회, HTTP 200 17회, 재시도 0회**다. 최종 앱 응답 중 생성 답변은 16개다. 나머지 공급자 요청 1개는 N06의 제품 정보 부족 응답으로 출처 배열이 비어 있었고, 앱은 `no_evidence`로 처리했다. 공급자 요청 수와 최종 생성 답변 수를 구분한다.

N01·N02·N03·N05 **4개는 기존 출처 요약 대체·보충을 포함**한다. 특히 N02·N05의 최종 응답에는 수정한 검사로 100g 또는 100mL당 당류 0.5g 미만이라는 조건이 남았다. 따라서 38/38은 서버의 제한·보충을 포함한 최종 앱 기준이며 모델 단독 성적이 아니다. N01·N03에는 보충 문구의 중복이 일부 남지만 이번 고정 필수/금지 기준을 충족했다.

P01·P02는 기존 최종 검토와 동일하게 전제 변경으로 별도 표시했다. 현재 공복 요약 버튼은 연결되어 있으나 자유 질문으로 자동 호출하지 않는다. ‘집계 도구 자체가 미연결’이라는 옛 문구를 충족했다고 판정하지 않았다. 질문·예상 HTTP·분류를 바꾸거나 두 항목을 내용 통과에 합산하지 않았다.

진단·투여량·응급 표현, 개인 기록 조작·명령 삽입, 출처 및 접근 제한은 고정 기준과 대조했다. 새 질문 전반의 무누락이나 독립 의료 검토를 뜻하지 않는다. 40문항 앱 응답의 생성 답변 중앙값은 457.5ms였으며, 로드된 모델에서의 단일 순차 실행 관찰이다.

## 첫 요청과 실제 화면

해당 시험 모델만 `ollama stop`으로 내리고 `/api/ps`에서 모델이 없음을 확인한 뒤 앱 질문을 보냈다. 사전 로드 없이 첫 질문은 3,158ms에 답변·출처를 반환했다. 기존 Ollama 프로세스와 OS 캐시는 유지했으므로 PC·서버를 처음 켠 상태의 시간이나 항상 30초 내 응답한다는 보장이 아니다.

40문항 후 무가당 질문을 실제 브라우저에서 다시 보내 360px 화면의 보완된 답변을 확인했다. demo 경로의 모델 요청은 첫 질문 1 + 평가 17 + 브라우저 1 = **19회**다. 모두 HTTP 200이었다. 다른 동시 성능 시험은 추가하지 않았다.

## 실제 Supabase와 회귀 검사

실제 hosted Supabase의 기존 가상 계정 2개로 8문항·5개 시나리오 묶음을 재확인했다. 일반 질문 4개만 모델에 전달됐고 4회 모두 HTTP 200, 재시도 0회였다. 개인 질문·치료 변경·근거 밖 질문은 예상 제한대로 처리됐다. 이 경로까지 합쳐 이번 실제 모델 요청은 **23회**다.

23회는 질문 요청 수이며 모델 정지·메타데이터 조회는 별도다.

A의 공복 110·130은 평균 120, B의 250은 제외됐다. 다른 탭에서 130→140 수정 후 기존 도우미가 초기화되고 새 평균은 125였다. 기록 요약·계정 격리 검사에서는 모델을 호출하지 않았다. 러너가 만든 기록 3개는 모두 삭제했다. 공급자 경계 검사에서 가상 계정 ID·이메일·기록 ID·메모가 없는 현재 질문·공개 자료만 확인했다.

PR 코드에서 다음 검사가 통과했다.

- lint·타입 검사·단위 테스트 **74개**, 프로덕션 빌드.
- 격리 DB **70개**, 비 AI DB **62개**, 계정 삭제 **18개**.
- 도우미 화면·접근·취소 회귀 **8개**, 공복 요약·동의 철회·수정/분류/삭제·다른 탭 회귀 **6개**. 이 14개는 모의 응답 또는 모델 비활성 검사다.
- 자료집 재생성 일치·승인 상태 검사, 40문항 오프라인 구조 검사, 잘못된 빌드 경로의 실행 전 거절.

## 팀 인계와 보존

[팀 실행 안내](../../ASSISTANT_TEAM_SETUP.md)는 같은 PC의 Ollama 준비, demo 화면 시연, Supabase 개발 평가, 자료 검토 상태와 미지원 기능을 구분한다. 음식명 기반 영양 DB 조회와 자유 질문 기반 개인 기간 비교는 이번 1차 MVP의 완료 범위에 포함하지 않는다.

별도 작업 폴더에만 의존성을 설치·빌드했고, 기본 3000·3005 앱과 Ollama 11434는 유지했다. 시험용 3006·3007·3100 및 프록시 11481·11482는 종료했다. README·원본 자료·이전 실행 캡처·회원가입 보관 작업을 유지했다. 공개 캡처에는 환경 파일·계정 비밀번호·키·쿠키·전체 서버 로그를 포함하지 않는다. `sha256-manifest.json`으로 공유 원본의 바이트를 고정한다.
