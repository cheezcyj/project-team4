## R01. 어제와 오늘 혈당 변화 어때?

**유형·우선순위:** 개인 기록 · P0

**답변 초안 / 출력 내용**

같은 측정 조건의 어제 {n_yesterday}건 평균은 {mean_yesterday}, 오늘 현재까지 {n_today}건 평균은 {mean_today} mg/dL입니다. 차이는 {delta} mg/dL입니다. 비교 기간과 조건, 건수를 함께 표시합니다. 1건씩이면 평균 추세 대신 두 측정값의 차이로 설명합니다.

**필요한 입력:** 인증된 본인 기록 / 실제 측정 일시·시간대 / 혈당값·단위 / 측정 상황 및 식사 구분

**근거**

- APP_RECORDS / 사용자가 앱에 직접 저장하는 혈당·식사 기록: 수치 조회·차이 계산은 프로그램 설계 기준
- KDCA_DIABETES / [당뇨병](<../../data/당뇨병 _ 국가건강정보포털 _ 질병관리청.pdf>) · PDF 11, 13페이지 · [공식 원문](https://health.kdca.go.kr/healthinfo/biz/health/gnrlzHealthInfo/gnrlzHealthInfo/gnrlzHealthInfoView.do?cntnts_sn=5305): 측정 상황·시각·생활 맥락 기록의 근거. 평균 계산식 자체를 정한 근거는 아님.

**적용 조건**

- 같은 측정 상황끼리 비교. 조건을 섞은 전체 평균으로 건강 개선을 판정하지 않음.
- Asia/Seoul 달력 날짜, 실제 측정 시각 기준. 오늘은 부분 기록.
- 현재 기록으로 식사·운동이 변화의 원인이라고 추론하지 않음.

**정보가 부족하거나 범위를 벗어나면:** 한쪽 날짜에 같은 조건의 기록이 없으면 변화량을 계산하지 않고 있는 날짜의 기록만 안내한다. 측정 상황이 없으면 조건이 불명확함을 표시한다.

## R02. 최근 7일 공복 혈당 평균 알려줘.

**유형·우선순위:** 개인 기록 · P0

**답변 초안 / 출력 내용**

오늘을 포함한 최근 7개 달력 날짜의 공복 기록은 {n_records}건, {n_days}일에 있습니다. 해당 기록의 산술평균은 {mean} mg/dL이며 일별 건수와 값도 함께 보여 줍니다. 오늘 기록은 현재까지 집계했습니다.

**필요한 입력:** 인증된 본인 기록 / 기간 기준 / 실제 측정 일시·시간대 / 공복 여부 / 혈당값·단위

**근거**

- APP_RECORDS / 사용자가 앱에 직접 저장하는 혈당·식사 기록: 최근 7일의 정의·기록별 산술평균은 제품 설계 제안
- KDA_GUIDELINE_2025 / [2025 당뇨병 진료지침 요약문 수정본(26.2.12)](<../../data/2025 당뇨병 진료지침_요약문_수정본(26.2.12).pdf>) · PDF 11페이지 · 책자 20-21쪽 · [공식 원문](https://diabetes.or.kr/bbs/?code=guide&mode=view&number=2099): 자기혈당측정 시기·횟수 개별화와 CGM 지표 구분

**적용 조건**

- 평균의 분모는 기록 건수. 기록이 없는 날을 0으로 채우지 않음.
- 수기 기록 평균을 실제 24시간 평균이나 CGM 시간범위 비율로 설명하지 않음.

**정보가 부족하거나 범위를 벗어나면:** 공복으로 확인된 기록이 없으면 계산하지 않는다. 일부 날짜가 비면 누락 날짜·기록 수를 안내한다.

## R03. 오늘 식사 메모에 뭐라고 적었지?

**유형·우선순위:** 개인 기록 · P1

**답변 초안 / 출력 내용**

오늘 실제 측정 시각에 연결된 기록별로 측정 시각·측정 상황·입력한 메모와 선택한 음식을 보여 줍니다. 식사 시각을 별도로 저장하지 않았다면 측정 시각을 식사 시각으로 바꿔 표시하지 않습니다.

**필요한 입력:** 인증된 본인 기록 / 실제 측정 일시·시간대 / 입력한 식사 메모 / 선택한 음식이 있으면 해당 연결

**근거**

- APP_RECORDS / 사용자가 앱에 직접 저장하는 혈당·식사 기록: 현재 계획한 메모와 음식 선택 데이터 조회

**적용 조건**

- 자유 메모에서 음식 코드·먹은 양을 자동 확정하지 않음.
- 식사 시각과 측정 시각은 다른 의미.

**정보가 부족하거나 범위를 벗어나면:** 해당 날짜의 메모가 없으면 메모 없음으로 답한다. 선택 음식이나 양이 빠졌다면 영양 합계를 만들지 않는다.

## F01. 이 음식 영양정보가 어떻게 돼?

**유형·우선순위:** 음식 영양정보 · P0

**답변 초안 / 출력 내용**

선택한 {food_name}의 {basis} 기준 열량·탄수화물·당류·단백질·지방 등을 보여 줍니다. 조회한 식품코드, 음식/가공식품 구분, 기준량, 제공기관을 함께 표시합니다. 빈 성분 값은 정보 없음으로 표시합니다.

**필요한 입력:** 음식 텍스트 검색어 / 검색 결과에서 확인한 식품코드

**근거**

- FOOD_CSV / [식품영양성분_핵심컬럼.csv](<../../data/csv.zip>): 식품명·식품코드·기준량·영양성분 열 직접 조회

**적용 조건**

- 제품·조리법이 다른 동명이름 후보가 있으면 사용자가 선택.
- 양을 입력하지 않았으면 기준량 정보만 답하며 실제 먹은 양으로 표현하지 않음.

**정보가 부족하거나 범위를 벗어나면:** 음식이 불명확하면 후보를 제시해 선택받고, 검색 결과가 없으면 수치를 추측하지 않는다. 결측은 0으로 대체하지 않는다.

## F02. 이 음식을 200g 먹었으면 영양성분은 얼마야?

**유형·우선순위:** 음식 영양정보 · P0

**답변 초안 / 출력 내용**

100g 기준 음식의 200g 섭취량은 확인된 각 성분에 2를 곱해 계산합니다. 원래 기준량과 입력한 양, 계산된 성분을 구분해 보여 줍니다. 원본에서 빠진 성분은 계산 후에도 정보 없음입니다.

**필요한 입력:** 확인한 식품코드 / 섭취량 숫자 / 섭취량 단위 / 원본 기준량·단위

**근거**

- FOOD_CSV / [식품영양성분_핵심컬럼.csv](<../../data/csv.zip>): 성분×섭취량/기준량의 동일 단위 환산. 의학적 섭취 권고가 아닌 산술 계산.

**적용 조건**

- g 기준과 ml 기준을 혼합하지 않음.
- 식품중량이나 1인분 문구만으로 사용자가 먹은 양을 확정하지 않음.

**정보가 부족하거나 범위를 벗어나면:** 100ml 자료에 g만 주어지면 밀도 없이 계산하지 않고 같은 단위의 양을 확인한다. 1공기·1인분만 주어져 중량이 불명확하면 기준량 정보를 우선 안내한다.
