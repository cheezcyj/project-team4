# 시연용 가상 혈당 기록

작성일: 2026-10-21. **가상 사용자 2명의 14일 범위 기록 67건**을 준비했다. 사용자 A 40건, 사용자 B 27건이며 누락 날짜·누락 측정 상황을 포함한다. 실제 환자·조사 대상자 데이터는 사용하지 않았다. 이 작업은 JSON 자료 생성이며 앱·DB에 사용자나 기록을 추가하지 않는다.

## 파일

- [가상 사용자·혈당 기록](../fixtures/demo/glucose_records.json)
- [검증용 사례 10개와 기대 결과](../fixtures/demo/scenarios.json)
- [생성 정보·검사 범위·파일 해시](../fixtures/demo/manifest.json)
- [생성 스크립트](../scripts/prepare_demo_data.py)

고정 기준 시각은 **2026-10-21 12:00 KST**, 기록 범위는 **2026-10-08~10-21**이다. 실행하는 날의 현재 시각을 기준으로 삼지 않아 동일한 결과를 재현할 수 있다. 앱에서는 고정 시연 날짜 선택이나 별도 테스트 시계를 연결해야 한다.

## 기록 필드와 연결 방법

| 필드 | 의미·제약 |
| --- | --- |
| `id`, `user_id` | 결정적 UUID로 만든 가상 식별자. 실제 Auth 사용자가 아니므로 테스트 계정에 명시적으로 매핑 |
| `glucose_mg_dl`, `glucose_unit` | 가상 혈당값과 mg/dL 단위. 임상적 정상 범위·개선 효과의 근거로 사용하지 않음 |
| `measured_at` | 실제 측정 시각 역할의 가상 시간. UTC 오프셋을 포함해 저장 |
| `measurement_timezone` | 한국 달력 날짜로 해석할 때 `Asia/Seoul` 사용 |
| `measurement_context`, `meal_period` | 측정 상황과 식사 구분을 분리한 개발용 코드. 팀 ERD 확정 시 매핑 |
| `meal_memo` | 일반 가상 문장·빈 문자열·null 사례 포함. 메모에서 음식·양을 확정하지 않음 |
| `selected_foods` | 빈 배열. 식품코드·섭취량·영양 합계는 검증 없이 채우지 않음 |
| `created_at`, `updated_at` | 나중에 입력·수정한 사례용 시각. 전체 수정 이력을 제공하지 않음 |
| `is_synthetic`, `scenario_tags` | 가상 자료 표시와 사례 설명용 필드. 앱 운영 필드로 확정한 것은 아님 |

가상 값은 규칙으로 만들었으며, 국민건강영양조사나 CGMacros를 복제하거나 학습해 생성하지 않았다. 식후 2시간 표시는 예시 선택값이며 식사 시작 시각이 없어 경과시간 준수 여부를 검증한 자료는 아니다.

## 확인할 사례

| ID | 사례 | 기대 결과 |
| --- | --- | --- |
| D01 | 어제·오늘 같은 조건의 공복 기록 | 120 → 110 mg/dL, 각 1건, 차이 -10. 두 측정값 비교로 설명 |
| D02 | 한쪽 날짜의 공복 기록 없음 | 변화량 미계산. 없는 기록을 0으로 채우지 않음 |
| D03 | 오늘 포함 최근 7개 달력 날짜 | 공복 6일·6건 평균 118.3 mg/dL, 10월 16일 누락 안내 |
| D04 | 다른 사용자 기록이 같은 날짜에 존재 | 본인 범위로 조회. 실제 인증·권한 검증은 앱에서 수행 |
| D05 | 측정 다음 날 저장·수정 | 저장일 대신 실제 측정일인 10월 20일 기록으로 분류 |
| D06 | UTC 날짜와 한국 날짜가 다름 | UTC 10월 20일 15:05는 한국 10월 21일 00:05 기록 |
| D07 | 식사 메모·음식 연결 없음 | 메모 없음. 음식과 영양정보를 추측하지 않음 |
| D08 | 같은 시각·값의 서로 다른 기록 ID | 2건 보존, 중복 의심을 확인할 수 있게 하고 임의 삭제하지 않음 |
| D09 | 아침·저녁의 식후 2시간 기록 | 식사 구분별로 보존해 서로 다른 조건을 무조건 혼합하지 않음 |
| D10 | 해당 날짜 기록 전체가 없음 | 기록 없음. 보간·생성하거나 0으로 대체하지 않음 |

이번 검사는 **가상 데이터·시간·수작업 기대값의 일관성 검사**다. 실제 서비스의 인증·접근 제어·조회 코드·그래프·챗봇 답변이 통과했다는 뜻은 아니다. 해당 기능을 연결한 뒤 이 사례로 확인해야 한다.

## 재현

추가 패키지 없이 Python 3.10 이상에서 실행한다. 기존 임상·공공 원본 자료는 읽거나 수정하지 않는다.

```powershell
python scripts/prepare_demo_data.py
```

출력 경로를 바꾸어 별도 생성할 수도 있다. 기본 출력은 Git으로 공유할 수 있는 `fixtures/demo/`이며 파일마다 가상 자료 표시가 있다.

```powershell
python scripts/prepare_demo_data.py --output-dir .tmp/research/demo-reproduction
```

다음 준비 작업은 [데이터 활용안](research/CHATBOT_DATA_PLAN.md)에 정리한 식품 검색용 추출본과 질문별 근거 단락이다. 출처는 [데이터 출처 등록부](research/DATA_SOURCES.md)에서 관리한다.
