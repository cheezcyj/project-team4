# 이어드림

혈당과 식사를 기록하고 일지·캘린더·리포트로 살펴보는 웹 앱입니다. 이 저장소는 **개인 PC에서 설치하고 실행하는 소스**를 제공합니다.

- 혈당 기록: 측정 상황 10가지, 식사 시간대, 추가·수정·삭제
- 식사 기록: 음식 검색, 자유 입력, 선택 당시 영양정보 보관
- 통합 일지·월별 캘린더·최근 7일 및 14일 리포트·동일 조건 기간 비교
- 실제 측정점과 시간순 연결선을 표시하는 그래프 및 원본 값 표
- CSV 빈 양식 다운로드, 열 연결, 미리보기, 일괄 저장, 중복 방지
- 맞춤 정책·혜택과 선택 조건 설정

**도우미는 화면 틀만 있으며 AI 모델·질문 전송·대화 저장은 연결하지 않았습니다. 건강 뉴스는 빈 목록으로 유지하며 뉴스 API도 연결하지 않았습니다.**

## 가장 빠른 로컬 실행

Node.js 22.9 이상과 npm이 필요하며, Node.js 24를 권장합니다. 아래 명령은 저장소 폴더에서 실행합니다.

```sh
npm ci
npm run build
npm run start:demo
```

브라우저에서 [http://127.0.0.1:3000](http://127.0.0.1:3000)을 열고 **가상 계정 A로 시작** 또는 **가상 계정 B로 시작**을 선택합니다. 처음에는 이용 안내에 동의한 뒤 기록을 추가할 수 있습니다. 이 모드는 **Supabase 계정이나 환경파일 없이** 실행됩니다.

서버를 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 다시 실행할 때는 `npm run start:demo`만 사용하면 됩니다. 소스를 수정한 뒤에는 다시 빌드합니다.

개발 중 변경을 즉시 확인하려면 다음 명령을 사용합니다. 같은 포트에서 두 서버를 동시에 실행하지 않습니다.

```sh
npm run dev:demo
```

3000번 포트를 이미 사용하고 있다면 다른 포트로 실행합니다.

```powershell
# PowerShell
$env:PORT = "3005"
npm run start:demo
```

```sh
# macOS / Linux
PORT=3005 npm run start:demo
```

위 경우 접속 주소는 [http://127.0.0.1:3005](http://127.0.0.1:3005)입니다.

## 로컬 시연 데이터

시연 기록은 실행한 폴더의 `.local/demo-data.json`에 저장되며, 서버를 다시 실행해도 유지됩니다. 서버를 재시작하면 가상 계정을 다시 선택합니다. 시연 서버는 본인 PC의 루프백 주소에서만 이용할 수 있습니다.

가상 계정은 기능 확인을 위한 계정입니다. **실제 건강정보나 개인정보를 입력하지 마세요.** 이 앱은 진단이나 치료를 제공하지 않습니다.

저장소에는 실제 사용자 데이터·계정·환경파일·원본 식품 CSV를 포함하지 않습니다. 기본 음식 검색은 소스에 포함된 USDA 공개 식품 8개를 사용합니다. 별도 대용량 음식 자료는 포함하지 않습니다. 영양값이 없는 항목은 0으로 바꾸지 않으며, 검증된 같은 단위에 한해서만 섭취량을 환산합니다.

그래프의 점은 실제 입력한 측정값입니다. 연결선은 측정값을 시간순으로 이은 표시이며, 측정하지 않은 시간의 값을 뜻하지 않습니다. 날짜와 기간은 한국 시간을 기준으로 계산합니다.

## 본인 Supabase 연결하기 — 선택 사항

로컬 시연만 사용할 때는 이 단계가 필요하지 않습니다. 회원가입·이메일 로그인과 DB 저장을 확인하려면 **본인의 별도 테스트 프로젝트**를 준비합니다. 이 저장소에는 운영 프로젝트의 접속 정보가 없습니다.

1. 새 빈 Supabase 프로젝트에 아래 SQL을 순서대로 적용합니다. 이미 적용한 파일은 다시 실행하지 않습니다.

   | 순서 | 파일 | 내용 |
   |---|---|---|
   | 1 | [20261020000100_glucose_records.sql](supabase/migrations/20261020000100_glucose_records.sql) | 동의·혈당 기록 및 사용자별 권한 |
   | 2 | [20261021000100_self_service_account.sql](supabase/migrations/20261021000100_self_service_account.sql) | 본인 계정 삭제 |
   | 3 | [20261021000200_non_ai_features.sql](supabase/migrations/20261021000200_non_ai_features.sql) | 식사·음식·설정·CSV 저장 기능 |
   | 4 | [20261021000300_reviewed_catalog.sql](supabase/migrations/20261021000300_reviewed_catalog.sql) | 공개 기본 음식·정책 자료 |
   | 5 | [20261021000400_meal_stale_conflict.sql](supabase/migrations/20261021000400_meal_stale_conflict.sql) | 식사 수정 충돌의 즉시 오류 응답 |

2. `.env.local`이 없는 새 환경에서 `.env.example`을 복사해 `.env.local`을 만듭니다. 기존 설정이 있다면 덮어쓰지 않습니다.
3. 본인 프로젝트의 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 입력합니다. 키는 **publishable key**를 사용합니다. `service_role`이나 관리자 비밀키는 사용할 수 없습니다. 실제 설정 파일은 공유하지 않습니다.
4. Supabase의 이메일 로그인·신규 가입 설정을 확인합니다. 이메일 확인이 필요한 프로젝트에서는 확인을 마쳐야 로그인할 수 있습니다. 로컬 Site URL은 `http://127.0.0.1:3000`입니다. 다른 포트를 사용하면 같은 포트로 맞춥니다.
5. `npm run dev`로 실행하고 앱에서 본인 테스트 계정을 만듭니다. 최적화된 실행은 `npm run build` 다음 `npm start`를 사용합니다.

앱 서버가 환경설정을 읽어 본인 사용자 권한으로 DB에 접근합니다. DB에도 사용자별 행 접근 제어가 적용됩니다. `npm run dev:demo`와 `npm run start:demo`는 Supabase 대신 로컬 가상 계정 모드를 선택합니다.

현재 이용 안내와 동의 버전은 가상 데이터 시연용입니다. 실제 개인 건강정보를 받는 서비스로 전환하려면 운영 주체와 보관·삭제 정책 등을 별도로 확정해야 합니다.

## CSV 가져오기

앱의 **CSV 가져오기 → CSV 템플릿 다운로드**에서 열 이름만 있는 빈 양식을 받습니다. 두 번째 줄부터 기록을 작성하고 UTF-8 CSV로 저장한 뒤 업로드합니다.

양식에는 측정 시각·혈당·측정 상황·식사 시간대·식사 메모·혈당 단위의 6개 열이 있습니다. 단위는 `mg/dL`을 사용합니다. 파일은 2MiB, 데이터는 1,000행까지 지원합니다. 미리보기에서 오류를 수정한 뒤 전체 기록을 저장합니다. 파일 원본과 파일명은 저장하지 않습니다.

## 검사 명령

```sh
npm run lint
npm run typecheck
npm test
```

`npm test`는 단위 검사와 메모리 안의 PostgreSQL 검사를 실행합니다. 실제 Supabase에 접속하거나 운영 DB를 수정하지 않습니다. 전체 정적 검사·테스트·빌드를 묶어서 실행하려면 `npm run check`를 사용합니다.

브라우저 검사는 Chromium을 설치한 뒤 실행합니다.

```sh
npx playwright install chromium
npm run test:e2e
```

브라우저 검사 명령은 앱을 빌드한 다음 3100번 포트에서 별도 시연 서버를 실행합니다. 3100번 포트는 비워두어야 합니다. 검사 데이터와 결과는 `.local/` 아래에 생성되며 평소 시연 기록과 분리됩니다.

## 소스 구조

| 경로 | 역할 |
|---|---|
| `src/app/` | 화면 주소와 API |
| `src/components/` | 기능별 화면과 공통 UI |
| `src/lib/domain/` | 날짜·입력 검사·계산 규칙 |
| `src/lib/server/` | 로그인·저장·사용자별 접근 처리 |
| `scripts/` | 로컬 실행과 음식 자료 변환 도구 |
| `supabase/migrations/` | DB 생성·변경 SQL |
| `supabase/tests/` | 격리 DB 검사 |
| `tests/` | 단위·브라우저 검사 |

환경설정은 비어 있는 `.env.example`만 공유합니다. `.local/`, 실제 환경파일, 설치한 패키지와 빌드 결과는 공유 대상이 아닙니다.
