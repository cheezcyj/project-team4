# 이어드림

**혈당과 식사 기록을 한곳에서 살펴보는 건강 기록 웹 앱**

이어드림은 일상의 혈당과 식사를 기록하고, 일지·캘린더·리포트로 확인할 수 있는 프로젝트입니다. 기록 관리에 더해 건강 소식, 일반 건강정보를 설명하는 도우미, 동의 기반 공복 기록 요약을 제공합니다.

이 저장소에는 웹 앱 소스와 로컬 실행 환경이 포함되어 있습니다. 별도 계정이나 데이터베이스를 준비하지 않아도 가상 계정으로 주요 화면과 기록 기능을 살펴볼 수 있습니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 혈당 기록 | 혈당값·측정 시각·측정 상황을 입력하고 기록을 수정·삭제합니다. |
| 식사 기록 | 공개 음식 자료를 검색하거나 음식명을 직접 입력해 식사 내역을 남깁니다. |
| 일지와 캘린더 | 혈당과 식사 기록을 날짜별로 함께 살펴봅니다. |
| 혈당 리포트 | 실제 측정값을 그래프로 확인하고 기간별·측정 상황별 기록을 비교합니다. |
| CSV 가져오기 | 빈 양식을 내려받아 작성하고, 미리보기와 오류 확인 후 기록을 가져옵니다. |
| 건강 뉴스 | 보건복지부 건강 소식의 제목·짧은 발췌·출처와 원문 링크를 제공합니다. |
| 도우미 채팅 | 근거 자료를 바탕으로 일반 건강정보를 설명하고, 대화방별로 질문과 답변을 보관합니다. |
| 공복 기록 요약 | 별도 동의 후 최근 7일 공복 기록을 집계하고 조회 당시의 요약을 대화에 저장합니다. |
| 마이페이지 | 성별·만 나이·키·몸무게를 선택적으로 입력하고 저장·수정·삭제합니다. |

대화방을 닫거나 새로고침해도 저장한 대화를 다시 확인할 수 있습니다. 대화방 삭제와 원래 건강 기록 삭제는 구분되며, 회원 탈퇴 시 해당 계정의 대화 이력도 함께 삭제됩니다.

## 사용 흐름

1. 로그인하고 이용 안내를 확인합니다.
2. 혈당이나 식사 기록을 입력합니다.
3. 일지·캘린더·리포트에서 기록을 살펴봅니다.
4. 필요한 경우 건강 소식을 읽거나 도우미에 일반 건강정보를 질문합니다.
5. 공복 기록 요약은 기록 조회와 요약 저장에 동의한 뒤 확인합니다.

모바일과 데스크톱에서 사용할 수 있는 반응형 화면으로 구성되어 있습니다.

## 로컬에서 실행하기

**Node.js 22.9 이상, npm, Git**이 필요합니다. 가상 계정 모드는 Supabase 설정 없이 실행할 수 있습니다.

PowerShell:

```powershell
git clone https://github.com/cheezcyj/project-team4.git
cd project-team4
npm ci
$env:ASSISTANT_ENABLED = "1"
$env:ASSISTANT_ALLOW_DRAFT_PREVIEW = "0"
npm run dev:demo
```

macOS·Linux에서는 저장소를 받은 뒤 `npm ci`로 설치하고 다음과 같이 실행합니다.

```sh
ASSISTANT_ENABLED=1 ASSISTANT_ALLOW_DRAFT_PREVIEW=0 npm run dev:demo
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)에 접속해 **가상 계정 A** 또는 **가상 계정 B**를 선택하고 이용 안내에 동의합니다. 가상 계정에서는 직접 만든 예시 데이터로 기능을 확인합니다. 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

- 혈당·식사 기록, 리포트, 프로필과 공복 기록 요약은 AI 모델 없이 사용할 수 있습니다.
- 일반 AI 답변에는 별도로 준비한 로컬 모델이 필요합니다. 건강 뉴스와 공개 건강자료 조회에는 인터넷 연결이 필요합니다.
- 기본 실행 데이터는 `.local/`에 보관되며 서버를 다시 실행해도 유지됩니다. 가상 계정 모드의 기록은 해당 PC에 저장됩니다.

최적화된 빌드로 실행하려면 개발 서버를 종료한 뒤, 위 환경변수가 설정된 터미널에서 `npm run build`, `npm run start:demo`를 차례로 실행합니다.

### 도우미 모델 연결

Qwen3.5와 Gemma 4 등 로컬 모델을 연결할 수 있습니다. llama.cpp로 GGUF 모델을 실행하거나, Ollama의 호환 API를 앱에 연결합니다.

| 모델 예시 | GGUF 자료 | 이 프로젝트의 확인 범위 |
|---|---|---|
| **Qwen3.5 2B** | [Qwen3.5-2B-GGUF](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF) | `Q4_K_M` 구성으로 로컬 실행기·공통 안내문 재사용·답변 저장 확인 |
| **Qwen3.5 0.8B** | [Qwen3.5-0.8B-GGUF](https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF) | 비교할 수 있는 대안 모델. 이 앱에서의 실행은 미검증 |
| **Qwen3.5 4B** | [Qwen3.5-4B-GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF) | 비교할 수 있는 대안 모델. 이 앱에서의 실행은 미검증 |
| **Gemma 4 E4B** | [gemma-4-E4B-GGUF](https://huggingface.co/ggml-org/gemma-4-E4B-GGUF) | 기존 QAT 텍스트 GGUF를 Ollama로 가져와 연결한 검증 기록 있음 |
| **Gemma 4 E2B** | [gemma-4-E2B-GGUF](https://huggingface.co/ggml-org/gemma-4-E2B-GGUF) | 비교할 수 있는 대안 모델. 이 앱에서의 실행은 미검증 |

Gemma 4 E4B의 기존 검증은 [Ollama 연결 방식](docs/ASSISTANT_OLLAMA.md)을 사용했습니다. 표의 GGUF 링크가 모두 당시 검증한 파일과 동일한 것은 아니며, 공통 안내문을 재사용하는 새 실행기의 Gemma 호환성과 속도는 별도 확인이 필요합니다. GGUF는 모델 파일 형식이므로 모델·양자화 방식·실행 프로그램 버전·PC 자원에 따라 동작과 속도가 달라집니다. 내려받을 파일의 이용조건도 함께 확인합니다.

로컬 실행기로 모델 준비를 마쳤다면 `npm run dev:assistant`로 앱을 실행합니다. Ollama 직접 연결은 해당 안내 문서의 설정과 실행 명령을 사용합니다.

설치 파일 준비, 인증 설정, 공개 건강자료와 초안 자료 선택, 실행 명령은 [로컬 도우미 연결 안내](docs/LOCAL_ASSISTANT.md)에 정리되어 있습니다. 모델 파일과 개인 인증 값은 저장소에 포함되어 있지 않습니다.

<details>
<summary>선택 사항: 본인의 Supabase 프로젝트 연결</summary>

회원가입·이메일 로그인과 계정별 DB 저장을 확인하려면 본인의 테스트 프로젝트를 준비합니다.

1. [DB 마이그레이션](supabase/migrations/)의 SQL을 파일명 순서대로 적용합니다. 기존 프로젝트에는 아직 적용하지 않은 파일만 실행합니다.
2. [.env.example](.env.example)을 참고해 `.env.local`을 만들고 `APP_MODE=supabase`, 본인의 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 설정합니다. 기존 환경파일은 덮어쓰지 않습니다.
3. Supabase의 이메일 로그인 설정과 로컬 Site URL을 확인합니다. 기본 주소는 `http://127.0.0.1:3000`입니다.
4. `npm run dev`로 실행하고 테스트 계정으로 가입합니다. 이메일 확인을 사용하는 프로젝트라면 확인을 마친 뒤 로그인합니다.

일반 로컬 체험에는 이 설정이 필요하지 않습니다. 환경파일과 계정 정보를 저장소에 올리거나 공유하지 않습니다.

## 데이터와 도우미의 범위

- **음식 자료:** 식품의약품안전처 발췌 자료와 USDA 기본 자료를 사용합니다. 식품명·영양정보만 포함하며 회원의 건강 기록은 포함하지 않습니다. 출처와 가공 내역은 [음식 자료 이용 안내](resources/foods/NOTICE.md)에서 확인할 수 있습니다.
- **건강 뉴스:** 기사별 이용조건을 확인한 소식에 출처와 원문 링크를 표시합니다. 사진·첨부파일·기사 전문은 제공하지 않습니다. 자세한 범위는 [건강 뉴스 안내](docs/HEALTH_NEWS.md)에 있습니다.
- **일반 건강정보:** 기본 연결은 MedlinePlus 건강 주제 요약을 사용하고 출처를 표시합니다. 도우미는 진단, 약물 용량 조절이나 개인별 치료 결정을 제공하지 않습니다.
- **프로필과 기록:** 현재 프로필 입력값이나 저장된 공복 요약을 AI 답변의 입력으로 사용하지 않습니다. 사용자가 직접 작성한 질문은 모델에 전달됩니다.

## 개발 명령

| 명령 | 용도 |
|---|---|
| `npm run dev:demo` | 가상 계정으로 개발 서버 실행 |
| `npm run build` | 웹 앱 빌드 |
| `npm run start:demo` | 빌드한 앱을 가상 계정 모드로 실행 |
| `npm run assistant:model -- --help` | 로컬 모델 실행 옵션 확인 |
| `npm run check` | 코드 규칙·타입·단위·DB 검사와 빌드 |
| `npm run test:e2e` | 브라우저 기능 검사 |

브라우저 검사는 `npx playwright install chromium`으로 Chromium을 준비한 뒤 실행합니다. 기본 자동 검사는 실제 AI 모델 없이 실행되며 운영 데이터베이스를 수정하지 않습니다.

## 소스 구조

```text
src/app/          화면 주소와 API
src/components/   기능별 화면과 공통 UI
src/lib/          입력 검사, 계산, 인증, 저장, 도우미 로직
resources/foods/  음식 자료와 출처 안내
scripts/          로컬 실행과 자료 처리 도구
supabase/         DB 마이그레이션과 SQL 검사
tests/            단위 검사와 브라우저 검사
```
