# 이어드림

혈당과 식사를 기록하고 일지·캘린더·리포트로 살펴보는 웹 앱입니다. 팀원이 **각자 PC에서 화면을 수정하고 기능을 실험할 수 있도록** 로컬 실행 환경을 제공합니다.

- 혈당·식사 기록의 추가, 수정, 삭제와 계정별 기록 분리
- 마이페이지에서 성별·만 나이·키·몸무게 선택 입력과 저장·수정·삭제
- 공통 음식 50,002개 검색, 기본 목록 무작위 100개 표시와 음식 직접 입력
- 통합 일지, 캘린더, 기간별 리포트와 실제 측정값 그래프
- CSV 빈 양식 다운로드, 미리보기, 일괄 저장과 중복 방지
- 이용조건을 확인한 보건복지부 건강 소식 조회, 검색과 원문 보기
- 도우미의 대화방 생성·조회·삭제, 저장한 대화 이어보기
- 별도 동의 후 최근 7일 공복 기록을 요약하고 대화에 보관

## 어떤 방식으로 실행하나요?

| 목적 | 실행 방식 | 필요한 것 |
|---|---|---|
| 화면 수정, 기록 기능, 공복 요약·대화방 보관 실험 | **가상 계정 모드 — 먼저 권장** | Node.js, npm |
| 일반 건강정보 AI 답변과 이어지는 대화 실험 | 가상 계정 + 로컬 모델 | 위 항목 + 같은 PC에서 실행 중인 호환 모델 서버 |
| 회원가입·로그인, 실제 DB 저장·권한 실험 | 별도 Supabase 테스트 프로젝트 | 본인이 만든 테스트 프로젝트와 테스트 계정 |

공복 요약은 앱이 기록을 계산하는 기능이므로 **AI 모델 없이 사용할 수 있습니다.** 일반 건강정보 답변은 모델을 따로 연결해야 합니다. 건강 뉴스는 서버가 보건복지부 공식 RSS와 기사별 이용조건을 확인해 가져오며 별도 API 키는 필요하지 않습니다. 뉴스 조회에는 인터넷 연결이 필요합니다.

## 1. 가장 빠른 실행: 가상 계정으로 시작하기

Node.js **22.9 이상**, npm, Git을 준비합니다. 아래 예시는 PowerShell 기준입니다.

```powershell
git clone https://github.com/cheezcyj/project-team4.git
cd project-team4
npm ci
$env:ASSISTANT_ENABLED = "1"
$env:ASSISTANT_ALLOW_DRAFT_PREVIEW = "0"
npm run dev:demo
```

이미 저장소를 받은 경우 해당 폴더에서 `npm ci`부터 실행합니다. 개인 환경파일이나 Supabase 설정은 필요하지 않습니다.

`dev:demo`와 `start:demo`는 저장소의 공개 음식 CSV를 검사하고 로컬 캐시를 자동으로 준비합니다. 별도 다운로드나 API 키 없이 **50,002개 음식**으로 검색·식사 기록을 실험할 수 있습니다. 출처와 재배포 조건은 [음식 자료 이용 안내](resources/foods/NOTICE.md)에 있습니다.

macOS·Linux에서는 설치 후 다음과 같이 실행합니다.

```sh
ASSISTANT_ENABLED=1 ASSISTANT_ALLOW_DRAFT_PREVIEW=0 npm run dev:demo
```

1. [http://127.0.0.1:3000](http://127.0.0.1:3000)을 엽니다.
2. **가상 계정 A로 시작** 또는 **가상 계정 B로 시작**을 선택합니다.
3. 이용 안내에 동의하고 테스트용 기록을 입력합니다.
4. 도우미를 열어 **기록 조회·요약 저장 동의**에 체크하고 **공복 기록 요약**을 누릅니다.

소스를 저장하면 개발 서버가 변경을 반영합니다. 종료는 실행한 터미널에서 `Ctrl+C`를 누릅니다. 서버를 재시작하면 가상 계정을 다시 선택하지만, 저장한 기록과 대화는 남아 있습니다.

> 가상 계정에는 직접 만든 예시 데이터만 입력합니다. 실제 건강정보, 이름, 연락처, 개인 검사 결과는 입력하지 않습니다. 이 앱은 진단이나 치료를 제공하지 않습니다.

### 빌드한 화면으로 시연하기

개발 중에는 `dev:demo`를 사용하고, 최적화된 빌드로 확인할 때는 개발 서버를 종료한 뒤 아래 명령을 사용합니다.

```powershell
npm run build
$env:ASSISTANT_ENABLED = "1"
$env:ASSISTANT_ALLOW_DRAFT_PREVIEW = "0"
npm run start:demo
```

같은 터미널의 환경변수는 유지됩니다. 새 터미널에서는 다시 설정합니다. 소스를 바꾼 뒤 `start:demo`로 확인하려면 다시 빌드해야 합니다. 두 서버를 같은 포트에서 동시에 실행하지 않습니다.

## 2. 팀원이 바로 해볼 실험

| 해볼 일 | 확인할 결과 |
|---|---|
| 건강 뉴스에서 검색·더 보기·새로 불러오기 | 허용된 소식의 제목·짧은 발췌·출처·이용조건·원문 링크 확인 |
| 식사 기록 페이지를 열고 새로고침 | 전체 50,002개 중 무작위로 고른 100개가 표시됨 |
| 음식 이름을 검색한 뒤 검색어 지우기 | 검색 중에는 해당 결과를 이름순으로 표시하고, 지우면 무작위 목록을 다시 선택 |
| 가상 계정 A에서 혈당·식사 기록을 추가하고 수정·삭제 | 일지·캘린더·리포트에 변경 반영 |
| A에서 로그아웃하고 B로 로그인 | A의 기록과 대화방이 B에게 보이지 않음 |
| 최근 7일 안의 공복 기록을 추가하고 도우미에서 조회·저장에 동의 | 공복 기록만 집계한 요약과 조회 시각이 대화에 남음 |
| 도우미를 닫거나 페이지를 새로고침한 뒤 대화 목록 열기 | 저장한 대화방과 요약이 다시 표시됨 |
| 요약 이후 원래 혈당 기록을 수정하고 새 요약 요청 | 이전 요약은 조회 당시 값으로 유지되고, 새 요약이 추가됨 |
| 새 채팅을 만들고 대화방을 전환하거나 삭제 | 방별 이력이 분리되고, 삭제한 방의 이력만 제거됨 |
| 대화방 삭제 후 혈당 일지 확인 | 원래 혈당 기록은 유지됨 |
| 마이페이지에서 기본 정보를 입력하고 저장 동의 후 저장·수정·삭제 | 새로고침 후 저장값을 확인하고, 기본 정보만 삭제해도 다른 기록은 유지됨 |
| CSV 빈 양식에 예시 데이터를 넣고 가져오기 | 열 연결·오류 미리보기·저장·중복 방지 확인 |

같은 브라우저의 탭은 로그인 쿠키를 공유합니다. A와 B를 동시에 비교할 때는 일반 창과 시크릿 창 또는 서로 다른 브라우저를 사용합니다.

일반 AI 채팅은 아래 모델 연결 단계를 마친 뒤 실험합니다. 기본 실행에서 AI 답변 입력이 비활성인 것은 모델을 아직 연결하지 않았기 때문입니다.

### 건강 뉴스

건강 뉴스는 보건복지부 보도자료 중 건강 관련 소식을 조회합니다. 기사별 공공누리 제1유형 표시와 출처표시 조건을 확인한 항목만 제목·최대 180자 발췌·날짜·제공처·원문 링크로 표시합니다. 사진·첨부파일·기사 전문은 가져와 게시하지 않습니다. 자세한 출처와 제한은 [건강 뉴스 안내](docs/HEALTH_NEWS.md)에 있습니다.

뉴스는 최대 12개를 가져와 6개씩 표시하며, 검색은 현재 불러온 소식에서 수행합니다. 서버는 조회 결과를 15분간 공유하므로 새로 불러오기를 눌러도 그동안에는 같은 결과가 나올 수 있습니다. 갱신 실패 시 최근 6시간 안에 확인한 목록이 있으면 실패 안내와 함께 유지하고, 저장된 목록도 없으면 조회 실패로 표시합니다. 확인된 기사가 없는 상태와 연결 실패를 구분합니다.

### 음식 목록의 구성과 표시 방식

| 항목 | 동작 |
|---|---|
| 공통 자료 | 식약처 발췌본 50,000개 + USDA 기본 음식 8개 |
| 검색 제외 | 이름 앞의 공백 다음에 `?` 또는 `？`가 붙은 6개 항목 |
| 검색 가능한 전체 항목 | 50,002개 |
| 검색어가 없는 기본 목록 | 전체 후보에서 같은 항목을 중복으로 뽑지 않고 무작위 100개 선택 |
| 검색어가 있는 목록 | 이름 일부가 일치하는 결과를 이름순으로 최대 100개 표시 |
| 목록을 다시 뽑는 시점 | 페이지를 다시 열거나 새로고침할 때, 검색어를 지울 때 |

팀원들이 사용하는 전체 음식 자료는 같지만, 무작위로 표시하는 100개는 PC나 조회 시점마다 달라질 수 있습니다. 같은 식품명이라도 출처 코드·조리법·영양 수치가 다른 항목은 별도 항목으로 유지합니다. 이름 중간의 물음표는 앞에 붙은 물음표 제외 규칙의 대상이 아닙니다.

검색에서 제외해도 원본 CSV와 이미 저장한 식사 내역은 수정하거나 삭제하지 않습니다. 음식 선택 당시의 영양정보를 보관하며, 값이 없는 영양성분을 0으로 바꾸지 않습니다. 식약처 자료는 원본의 단위 표기를 보존하고 검증 전에는 섭취량에 따른 비례 환산을 하지 않습니다.

음식 CSV는 약 6.3MB이며 식품명·영양 수치 등 공개 필드 13개만 포함합니다. 회원·혈당·개인 식사·채팅 데이터가 아닙니다. 식약처 파일 자료의 이용조건은 **이용허락범위 제한 없음**, USDA 기본 자료는 **CC0**로 확인했으며, 출처·확인일·가공 내역·해시를 [음식 자료 이용 안내](resources/foods/NOTICE.md)에 기록했습니다. 공식 최신 전체 DB가 아닌 고정 발췌본을 사용합니다.

### CSV 입력 실험

앱의 **CSV 가져오기 → CSV 템플릿 다운로드**에서 열 이름만 있는 빈 양식을 받습니다. 두 번째 줄부터 예시 기록을 작성하고 UTF-8 CSV로 저장한 뒤 업로드합니다.

양식은 측정 시각·혈당·측정 상황·식사 시간대·식사 메모·혈당 단위의 6개 열입니다. 단위는 `mg/dL`, 파일 한도는 2MiB, 데이터 한도는 1,000행입니다. 미리보기에서 오류를 확인한 뒤 저장합니다. 파일 원본과 파일명은 보관하지 않습니다.

### 마이페이지 기본 정보

마이페이지의 **내 기본 정보**에서 성별·만 나이·키·몸무게 중 원하는 항목만 입력합니다. 한 가지 이상 입력하고 별도의 저장 동의에 체크해야 저장합니다. 수정할 때도 다시 동의하며, 입력값 오류나 다른 화면의 변경과 충돌하면 작성한 내용을 유지합니다. 저장·삭제 응답이 끊긴 경우에는 **저장된 정보 확인**으로 결과를 확인합니다.

프로필은 본인 계정에서만 확인·수정·삭제할 수 있고 회원 탈퇴 시 함께 삭제됩니다. 가상 계정 모드에서는 테스트용 값만 입력합니다. **현재 프로필을 도우미 답변에 사용하거나 AI·뉴스 제공처로 전송하지 않습니다.** 작성 중인 폼은 현재 탭의 메모리만 사용하며 로그아웃하면 지웁니다.

프로필 저장은 AI 모델 없이 사용할 수 있습니다.

## 3. 실험 데이터 보관과 새 실험 시작

가상 계정 데이터는 PC의 프로젝트 폴더 안에 저장됩니다.

| 파일 | 내용 |
|---|---|
| `.local/demo-data.json` | 가상 계정의 기록·설정·선택 입력한 프로필 |
| `.local/demo-data.json.assistant-conversations.json` | 가상 계정의 대화방, 질문·답변, 공복 요약 |
| `.local/food-catalog/team-f88a0e1dcd4f6075.json` | 공개 CSV에서 자동 생성한 공통 음식 캐시 |

기존 실험을 보존하면서 새 데이터로 시작하려면 서버를 종료하고 **새 파일명**을 지정합니다. 같은 이름을 다시 쓰면 해당 실험을 이어갑니다.

```powershell
$env:DEMO_DATA_FILE = ".local/experiments/chat-01.json"
$env:ASSISTANT_ENABLED = "1"
$env:ASSISTANT_ALLOW_DRAFT_PREVIEW = "0"
npm run dev:demo
```

macOS·Linux:

```sh
DEMO_DATA_FILE=.local/experiments/chat-01.json ASSISTANT_ENABLED=1 ASSISTANT_ALLOW_DRAFT_PREVIEW=0 npm run dev:demo
```

대화 파일도 같은 위치에 `chat-01.json.assistant-conversations.json`이라는 이름으로 생성됩니다. 기본 실험으로 돌아가려면 서버를 종료한 뒤 `DEMO_DATA_FILE`을 `.local/demo-data.json`으로 바꾸고 다시 실행합니다. 파일명만 바꿔도 이전 파일은 삭제되지 않습니다.

- 대화방은 계정당 50개, 방마다 질문·요약 합계 100개까지 저장합니다.
- X/ESC로 창을 닫아도 저장된 대화는 유지됩니다.
- 공복 요약은 요청할 때마다 조회·저장에 동의해야 합니다. 동의를 해제하거나 창을 닫아도 이미 저장된 요약은 남습니다.
- 대화방 삭제는 그 방의 질문·답변·요약을 함께 삭제합니다. 원래 혈당 기록은 유지합니다.
- 회원 탈퇴는 해당 계정의 모든 대화방도 삭제합니다.
- `.local/`과 실제 환경파일은 Git 제외 대상입니다. 팀원에게 데이터 파일이나 로그인 정보를 전달하지 않습니다.

공통 음식 자료만 미리 준비하려면 `npm run prepare:foods`를 실행합니다. 원본 CSV와 생성 결과의 SHA-256을 확인하며, 변경된 캐시는 자동으로 덮어쓰지 않습니다. 음식 자료의 버전은 [manifest.json](resources/foods/manifest.json)에 고정되어 있어 팀원마다 다른 최신 목록을 받는 일을 방지합니다.

별도 CSV로 실험할 때는 기존 `scripts/import-food-catalog.mjs`로 가져온 뒤 `FOOD_CATALOG_FILE`에 생성한 JSON 파일을 지정합니다. 직접 지정한 파일은 공통 목록으로 교체하지 않습니다. 공통 목록으로 돌아가려면 해당 환경변수를 해제하고 시연 서버를 재시작합니다. `DEMO_DATA_FILE` 변경은 기록·대화 저장 파일만 바꾸며 공통 음식 목록에는 영향을 주지 않습니다.

## 4. 일반 AI 채팅 연결 — 선택 사항

앱은 모델을 자동으로 다운로드하거나 실행하지 않습니다. **앱과 같은 PC**에서 OpenAI 호환 `/v1/chat/completions`를 제공하는 모델 서버가 실행 중이어야 합니다. 현재 연결은 루프백 주소만 허용합니다.

Ollama를 사용하는 경우 먼저 터미널에서 `ollama list`로 설치된 모델을 확인합니다. 팀에서 사용한 GGUF 등록 방법과 모델 조건은 [Ollama 연결 안내](docs/ASSISTANT_OLLAMA.md)를 참고합니다. 문서의 로컬 모델 별칭을 공개 다운로드 태그로 사용하지 않습니다.

기존 앱 서버를 종료한 뒤 아래 명령을 실행하고, 입력란에 **자신의 `ollama list`에 표시된 정확한 모델 이름**을 입력합니다.

```powershell
ollama list
$env:ASSISTANT_ENABLED = "1"
$env:ASSISTANT_MODEL_BASE_URL = "http://127.0.0.1:11434/v1"
$env:ASSISTANT_MODEL = Read-Host "ollama list에 표시된 모델 이름"
$env:ASSISTANT_MODEL_RESPONSE_FORMAT = "text"
$env:ASSISTANT_ALLOW_DRAFT_PREVIEW = "1"
npm run dev:demo
```

도우미에서 **대화 저장·AI 처리 동의**에 체크하고 일반 건강정보를 질문합니다. 이어서 같은 방에서 질문하면 기존 대화를 보면서 계속할 수 있습니다. 첫 답변에는 모델을 불러오는 시간이 추가될 수 있으며 앱의 요청 제한 시간은 30초입니다.

일반 질문에는 해당 방의 최근 일반 질문·답변 최대 2쌍(4개 메시지, 1,500자 이내)을 함께 전달합니다. 저장한 공복 요약, 원래 혈당·식사 기록, 계정 식별자는 모델 이력에 넣지 않습니다. 사용자가 질문에 직접 쓴 내용은 모델로 전달되므로 개인정보를 입력하지 않습니다.

기본 로컬 Ollama에는 `ASSISTANT_MODEL_API_KEY`를 비워둡니다. 별도로 인증을 설정한 모델 서버에서만 본인의 인증 값을 사용합니다. 키와 모델 파일은 저장소에 넣지 않습니다.

**현재 지식 자료는 검토 중인 초안입니다.** `ASSISTANT_ALLOW_DRAFT_PREVIEW=1`은 로컬 기능 실험용이며 자료의 공개 승인이나 모델·자료의 이용조건 검토를 대신하지 않습니다. 자세한 범위는 [도우미 팀 실행 안내](docs/ASSISTANT_TEAM_SETUP.md)를 확인합니다.

### 설정을 환경파일에 보관할 때

환경변수를 매번 입력하기 싫다면 `.env.example`을 참고해 본인 PC에만 `.env.local`을 만듭니다. 기존 파일이 있다면 덮어쓰지 않습니다. 가상 계정 실행에서 파일을 명시적으로 읽으려면 다음 명령을 사용합니다.

```sh
node --env-file-if-exists=.env.local scripts/run-demo.mjs
```

빌드한 앱은 `npm run build` 후 아래 명령으로 실행합니다.

```sh
node --env-file-if-exists=.env.local scripts/run-demo.mjs --production
```

현재 터미널에 이미 설정된 환경변수가 파일보다 우선합니다. 설정을 변경한 후에는 앱 서버를 재시작합니다. `.env.local`은 커밋하거나 메신저로 공유하지 않습니다.

## 5. 본인 Supabase 테스트 프로젝트 연결 — 선택 사항

가상 계정 실험만 할 때는 필요하지 않습니다. 회원가입·이메일 로그인과 계정별 DB 저장을 확인할 때 **별도 빈 테스트 프로젝트**를 만듭니다.

1. Supabase SQL Editor에서 아래 SQL 파일을 순서대로 실행합니다. 이미 적용한 파일은 반복 실행하지 않습니다.

2. `.env.local`이 없는 환경에서 `.env.example`을 복사합니다. 기존 설정은 덮어쓰지 않습니다.
3. `APP_MODE=supabase`를 유지하고 본인의 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 채웁니다. **publishable key**를 사용하며 `service_role`이나 관리자 비밀키는 사용하지 않습니다.
4. 공복 요약을 쓰려면 `ASSISTANT_ENABLED=1`로 설정합니다. `ASSISTANT_ALLOW_DRAFT_PREVIEW=0`, 빈 `ASSISTANT_SUPABASE_EVAL_USER_IDS`를 유지합니다.
5. Supabase의 이메일 가입·로그인 설정을 확인합니다. 로컬 Site URL은 `http://127.0.0.1:3000`이며 다른 포트로 실행하면 같은 포트로 맞춥니다.
6. `npm run dev`를 실행하고 테스트 계정으로 가입합니다. 이메일 확인이 필요한 설정이면 확인을 마친 뒤 로그인합니다. 최적화된 실행은 `npm run build` 다음 `npm start`입니다.

Supabase 모드의 대화는 계정별 DB에 저장됩니다. 같은 테스트 프로젝트에 연결한 앱에서 같은 계정으로 로그인하면 다른 기기에서도 저장한 대화를 확인할 수 있습니다. DB에는 사용자별 행 접근 제어가 적용됩니다.

소스를 내려받는 것만으로 DB가 변경되지는 않습니다. 기존 테스트 프로젝트를 업데이트할 때도 새로 추가된 SQL을 적용해야 합니다. `dev:demo`와 `start:demo`는 항상 로컬 가상 계정 모드를 선택합니다.

위 SQL의 기본 음식은 8개입니다. 별도 Supabase 테스트 DB에도 공통 50,000행을 추가하려면 `node scripts/import-food-catalog.mjs --input resources/foods/mfds-nutrition.csv --prepare-sql`로 SQL을 만들고, `.local/food-catalog.import.sql`을 본인의 테스트 DB에서 적용합니다. 이 명령 자체는 DB에 접속하지 않습니다. 가상 계정 모드에서는 이 과정이 필요 없습니다.

Supabase의 일반 설정에서는 초안 일반 답변이 차단됩니다. 별도의 제한된 개발 평가가 필요하면 [Supabase 평가 안내](docs/ASSISTANT_SUPABASE_EVAL.md)를 따릅니다. 현재 이용 안내와 동의는 가상 데이터 시연용이며, 실제 개인 건강정보를 받는 서비스 운영 정책을 대신하지 않습니다.

## 6. 검사 명령

저장소 폴더에서 실행합니다.

| 명령 | 확인 범위 |
|---|---|
| `npm run lint` | 코드 규칙 |
| `npm run typecheck` | TypeScript 타입 |
| `npm run prepare:foods` | 공통 음식 자료 검사·로컬 캐시 준비 |
| `npm run test:unit` | 계산·검증·도우미 동작 단위 검사 |
| `npm run test:db` | 메모리 안의 PostgreSQL에서 권한·저장·삭제·요약 검사 |
| `npm test` | 단위 검사 + DB 검사 |
| `npm run check` | 코드 규칙 + 타입 + 단위·DB 검사 + 빌드 |
| `npm run test:e2e` | 빌드 + 기본 브라우저 검사 + 공복 요약 전용 검사 |

`npm test`는 실제 Supabase에 접속하거나 운영 DB를 수정하지 않습니다. 기본 자동 검사는 실제 AI 모델이 없어도 실행할 수 있으며, 실제 모델 답변 품질·속도를 검증하는 검사는 아닙니다.

브라우저 검사는 Chromium을 준비한 뒤 실행합니다.

```sh
npx playwright install chromium
npm run test:e2e
```

검사 서버가 쓰는 **3100번 포트**를 비워둡니다. 검사 데이터는 `.local/e2e/`의 별도 파일을 사용하며 평소 시연 데이터와 분리됩니다. 결과는 `.local/playwright-results/`, HTML 결과는 `.local/playwright-report/`에서 확인합니다. 두 검사 묶음은 공통 결과 경로를 사용하므로 전체 결과는 실행한 터미널 출력도 함께 확인합니다.

## 소스 구조와 현재 범위

| 경로 | 역할 |
|---|---|
| `src/app/` | 화면 주소와 API |
| `src/components/` | 기능별 화면과 공통 UI |
| `src/lib/domain/` | 날짜·입력 검사·계산 규칙 |
| `src/lib/server/` | 로그인·저장·사용자별 접근 처리 |
| `src/lib/assistant/` | 도우미 자료 검색·모델 연결·대화 보관·공복 요약 |
| `resources/foods/` | 공개 음식 발췌본, 출처·이용조건과 해시 |
| `scripts/` | 로컬 실행·평가·음식 자료 변환 도구 |
| `supabase/migrations/` | DB 생성·변경 SQL |
| `supabase/tests/` | 격리 DB 검사 |
| `tests/` | 단위·브라우저 검사 |

기본 시연은 식약처 공개 자료 50,000개와 USDA 음식 8개를 합치고, 선행 `?`·`？` 항목 6개를 제외한 50,002개를 검색합니다. 음식 자료만 포함하며 모델 가중치는 포함하지 않습니다. 영양값이 없는 항목은 0으로 바꾸지 않고, 식약처 자료의 원본 단위가 검증되기 전에는 섭취량을 비례 환산하지 않습니다.

그래프의 점은 실제 입력한 값이며 연결선은 측정 시각 순서의 표시입니다. 측정하지 않은 시간의 값을 뜻하지 않습니다. 날짜와 기간은 한국시간을 기준으로 계산합니다.

공유하는 환경설정은 값이 비어 있는 `.env.example`을 기준으로 합니다. 실제 환경파일, 로컬 사용자 데이터, 생성한 음식 캐시, 설치 패키지, 빌드 결과, 개인 문서와 작업 기록을 커밋하지 않습니다. 재배포 조건을 확인한 공개 음식 CSV와 출처 안내만 `resources/foods/`에서 공유합니다.
